# 大模型低比特模型量化系统设计方案

> **系统定位**：构建通用的端云一体大模型低比特量化与模型交付系统，支持从 1-bit 到 16-bit 全范围量化，集成重要性矩阵（imatrix）张量感知与 UD（Unsloth Dynamic）自校准层级优化。  
> **验证基准**：Qwen3.8-27B（权重基准：BF16 GGUF）  
> **目标推理引擎**：llama.cpp（支持 CUDA/ROCm/CPU 全架构后端）  
> **算力参考基准**：NVIDIA RTX 3090 24GB, CPU: 16 Core 64GB, 磁盘: 100GB  

---

## 1. 系统背景与建设目标

在当前大模型轻量化落地的技术体系中，以 llama.cpp 为代表的 GGUF 格式已成为跨平台、端云异构设备上高能效部署的事实标准。然而，传统手工量化面临以下典型痛点：
1. **量化精度退化**：在 4-bit 甚至 2-bit/3-bit 极限压缩下，常规 Round-To-Nearest（RTN）截断引起严重语义坍塌与困惑度（PPL）飙升。
2. **缺乏统一自动化流水线**：从原始 safetensors 到 GGUF、重要性矩阵计算、层级量化规则配置流程繁琐，缺乏解耦的自动化工程框架。
3. **缺少领域动态感知**：现有量化方案难以结合自校准生成（UD 动态校准）保护模型输出的关键敏感张量。

本方案旨在打造**一套模块化、高鲁棒、可配置的通用量化系统**，达成以下目标：
- **全比特覆盖**：原生支持 1-bit（IQ1_S/M）到 16-bit（BF16/F16）全规格量化。
- **双引擎解耦架构**：将重要性矩阵生成器（`ImatrixGenerator`）与多档位量化引擎（`GGUFQuantizer`）解耦，支持流水线编排与分步单点调试。
- **全要素超参可控**：支持通过外部 YAML/JSON 配置量化档位、imatrix 策略（外部语料 vs 自校准）、层级保护规则（override-tensor）等。
- **严密对齐交付规范**：标准化产出 `bf16_gguf/`、`gguf/`、`calibration/`、`logs/` 全套产物。

## 3. 核心功能子系统设计

### 3.1 输入适配与基准转换子系统（BaseGGUFConverter）
- **输入多态兼容**：
  1. 若输入已是网络下载或预先准备的 `Qwen3.8-27B-BF16.gguf` 文件，直接进行头部校验后跳过转换阶段，直接进入量化；
  2. 若输入为 HuggingFace/ModelScope 的原始 `*.safetensors` 分片，自动加载分词器与配置，调用 `convert_hf_to_gguf.py` 输出单分片无截断的 BF16 GGUF。
- **断点自愈**：检测已有中间文件大小，若大于阈值（100MB+）则避免重复耗时转换。

### 3.2 重要性矩阵生成子系统（ImatrixGenerator）
针对不同业务场景，提供 4 种模式：
1. **NONE 模式**：禁用 imatrix，适用于快速验证与纯标准量化。
2. **DATASET 模式**：通过外部文本（WikiText-2、Alpaca、业务自定义领域语料）计算激活张量权重敏感度。
3. **SELF_GENERATED 模式**：**UD（Unsloth Dynamic）自校准策略**。利用原模型对高质量种子指令进行自回归采样生成自校准语料，输出分布与模型内部特征完全贴合。
4. **EXISTING 模式**：直接复用已有 `imatrix.gguf`，避免在 27B 尺度上重复耗费 30 分钟以上的 GPU 计算。

### 3.3 多档位低比特量化引擎（GGUFQuantizer）
- **1-bit 到 16-bit 全覆盖**：支持 `IQ1_S`, `IQ2_XXS`, `Q3_K_M`, `Q4_K_M`, `Q5_K_M`, `Q6_K`, `Q8_0` 以及 `BF16`。
- **智能降级与防御性告警**：对必须依赖 imatrix 的 IQ 档位（如 `IQ1_S`, `IQ2_XXS`, `IQ4_XS` 等），在无 imatrix 输入时自动发出严重降级告警，提醒开发者潜在的困惑度退化风险。
- **解耦的 UD 层级张量保护（Layered Override）**：
  允许独立于 imatrix 对关键网络结构做精细化量化约束：
  - 首尾敏感层（`blk.0.*`, `blk.1.*`, `blk.62.*`, `blk.63.*`）保留 `Q6_K` 或 `Q8_0`；
  - 注意力核心矩阵（`attn_q`, `attn_k`）以及门控层（`ffn_gate`, `ffn_up`）提升至 `Q5_K_M`；
  - 投机解码模块（`blk.64.nextn.*`）保持 `Q8_0` 高保真。

### 3.4 流水线编排与配置子系统（QuantPipeline & QuantConfig）
- 统一参数对象模型，支持从外部 JSON/YAML 加载全局超参。
- 自动化管理子进程生命周期、退出码监控、错误堆栈追踪与输出文件大小落盘。

## 5. 云端环境约束与资源优化策略

云端规格：**RTX 3090 (24GB 显存), CPU 16c 64GB, 磁盘 100GB**。

1. **显存峰值控制**：
   - 27B 规模在 BF16 精度下计算 imatrix 时，若全层卸载可能超额。框架参数中支持 `-ngl 99`，当显存吃紧时可调节为 `-ngl 50` 实现 CPU/GPU 混合分流。
   - `imatrix_chunk_size` 默认设为 512，避免大 chunk 序列导致显存 OOM。
2. **磁盘 100GB 预算管控**：
   - BF16 GGUF 约占 55GB，Q4_K_M 量化文件约占 15.5GB。两份共存时磁盘占用已达 70.5GB，余量仅 29.5GB。
   - 系统支持 `clean_intermediate_base=True` 选项；在批量生成多个量化档位时，可支持按需自动清理或阶段性替换。
3. **CPU 线程与算力加速**：
   - `-t 8` 或 `-t 16` 充分释放 16 核 CPU 算力。
