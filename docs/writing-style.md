# 文档写作规范

> 所有 PR 的文档评审以此为准。

## 1. 文档头部三要素

每篇正文文档开头必须包含：

```markdown
> **目标读者**：…
> **前置知识**：…
> **预计阅读**：…分钟
```

## 2. 性能数字规范

- 所有吞吐/延迟/显存数字必须附：硬件型号、驱动版本、框架版本、模型版本、复现命令。
- 禁止孤立数字。反例：`QPS 提升 2x`；正例：`A100 80G / vLLM 0.6.2 / Qwen2.5-7B-AWQ，压测命令见 §4，P99 延迟从 180ms 降至 92ms`。

## 3. 语言风格

- 中文正文，技术术语保留英文原词，首次出现加中文解释：KV Cache（键值缓存）。
- 标题层级从 `##` 开始，`#` 只用于文档标题。
- 代码块标注语言：` ```bash ` / ` ```python `。

## 4. 图片与附件

- 图片放同级 `images/`，相对路径引用。
- 单文件 >5MB（含 `.gguf` / `.mp4` / `.docx`）不进 git，走 GitHub Releases，文档中给下载链接。
- 日志样例脱敏后放 `logs/`，禁止 API Key 与内网地址。

## 5. 目录联动

新增/改名文档后必须同步更新：本目录 `README.md` + `docs/index.md`。
