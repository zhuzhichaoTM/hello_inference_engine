1为什么要量化：一个 float32 有多"奢侈"

模型里一个权重是 float32：1 位符号 + 8 位指数 + 23 位尾数 = 32 bit。而 4bit 量化只给每个权重留 4 bit（0~15 的整数）。下面看一个真实权重 0.23 的 32 个比特是如何被"展开"的。

w0 = 0.23（float32）→ ？bit
核心矛盾：7B 模型 F16 要 14GB；4bit 只要 ~4GB，能在消费级显卡/手机上跑。代价是每个权重只剩 16 个可能的取值——本片讲的就是 如何用两级缩放把这个代价压到最小。

2超级块切分：256 个权重 → 8 × 32

Q4_K 的最小处理单元是 256 个权重的超级块，再切成 8 个子块，每子块 32 个权重。颜色越深代表数值越大。每个子块将获得自己独立的 (scale, min) —— 因为相邻权重范围相近，局部缩放能显著降低误差。

3搜索最优 scale：一条 U 形误差曲线

对子块 0 的 32 个权重（范围 −0.78 ~ +0.87），量化器要找一对 (d, m) 使重建误差最小。下面的动画把 make_qkx2_quants 的搜索过程摊开给你看：格点间距 d 从粗到细扫过，右侧实时画出误差曲线——太粗误差大，太细会"装不下"导致截断，最低点就是最优解。

实际源码更进一步：搜索时以 |w|+av_x 作为每个权重的权重（重要的数不许偏太多），并对 m 也做微调（qkx3 还能借助预计算的 Hessian 权重），把误差再压低一截。

4逐权重吸附：float → 0…15

锁定 d = 0.11，m = −0.78 后，对每个权重执行 q = clamp(round((w − m)/d), 0, 15)。看 8 个代表权重如何"吸附"到最近的格点，并得到各自的 4bit 编码。

5scales 二级量化：8 个小数 → 8 个 6bit 整数

8 个子块各有一个 scale（这里演示 8 个代表值）。如果直接存 8 个 float32 太浪费——K 系列的做法：记录最大值 max_scale，把它折算成 fp16 的 d；其余 scale 按 63:1 的比例压成 6bit 整数。动画演示逐个翻转。

为什么要两级？只存 d 时，子块 scale = d × ls。ls 的取整误差被 d（很小）缩小，而 d 本身用 fp16 精确保存。大动态范围交给 fp16，细分辨率交给 6bit，两边都不吃亏。

6位打包：两个 6bit 值如何挤进 1.5 个字节

16 个 6bit 值（8×scale + 8×min）共 96bit，但字节是 8bit 的，直接存需要 16 字节还有空隙。源码的巧妙方案：以子块 5（ls=46, lm=26）为例——低 4bit 拼进一个字节，高 2bit 塞进另一个字节的空屋（bit6-7）。看比特如何搬家。

typedef struct {
    ggml_half d;         // 超级块 scale 主体 (fp16)
    ggml_half dmin;      // 超级块 min 主体 (fp16)
    uint8_t scales[12];  // 8 组 (sc, m)，6bit + 借位打包
    uint8_t qs[128];     // 256 个 4bit 值
} block_q4_K;            // sizeof = 2+2+12+128 = 144 字节

8反量化全链路：从一个字节还原出 0.21

为什么是 −m 而不是 +m？把偏移写成减法后，scale 恒为正，6bit 无符号空间一点不浪费；负号的不确定性被吸收进 m 的符号里。
// dequantize_row_q4_K()：每 64 个权重用两对子块尺度
for (j = 0; j < QK_K; j += 64) {
    get_scale_min_k4(is+0, x.scales, &sc, &m);
    d1 = d·sc;  m1 = min·m;
    get_scale_min_k4(is+1, x.scales, &sc, &m);
    d2 = d·sc;  m2 = min·m;
    for (l = 0; l < 32; ++l) *y++ = d1·(q[l] & 0xF) − m1;  // 低半字节
    for (l = 0; l < 32; ++l) *y++ = d2·(q[l] >> 4) − m2;  // 高半字节
    q += 32; is += 2;
}

9Q4_K_M 的 "M"：混合配方与最终体积

Q4_K_M 不是一种新编码，而是 llama-quantize 的一个预设配方：主体用 Q4_K，把少数精度敏感张量升级成 Q6_K。7B 模型约 4.1GB，是社区公认的"甜点"档位。

一屏回顾：256 个权重的完整旅程

F32 × 256（1024 字节）
  │  ② 切成 8×32 子块
  │  ③ 每子块搜索最优 (scale, min)          ← U 形误差曲线最低点
  │  ⑤ 8 个 scale/min → 6bit 整数 ls/lm     ← 二级量化，d=max/63 存 fp16
  │  ⑥ 6bit 拆成 4+2 借位打包 → scales[12]
  │  ④ q = clamp(round((w+m)/d), 0, 15)
  │     低4bit|高4bit 拼字节 → qs[128]
  ▼
block_q4_K = 144 字节   →   压缩 7.1×，4.5 bit/权重
  ▼
反量化 w = d·sc·q − dmin·m   ← 每个权重误差 ~0.02（示例子块）
