## 第一部分 · 基础题（第 1–60 题）

### 第 1 题
【题型：单选题】【难度：基础】
【题干】你把一个大模型部署到单卡做在线推理，发现 batch=1 时 MUL_MAT 算子的 GPU 利用率只有 10% 左右，而 batch 提到 64 后利用率涨到 70%。最合理的解释是？
【选项】
A. batch=1 时 CUDA 不允许使用 tensor core，所以只能用 CPU 算
B. batch=1 时 kernel 启动开销占满，与算术强度无关
C. batch=1 时算错了，结果需要重算
D. batch=1 时退化成 GEMV，每读一个权重只做一次乘加，算术强度极低，瓶颈在显存带宽而非算力
【正确答案】D
【详细解析】
1. **核心原理**：矩阵乘 `Y = W·X`，W 形状 [N,K]，X 形状 [K,B]。当 B=1 时是 GEMV（矩阵-向量乘），每个权重元素只被使用 1 次，算术强度约为 2 FLOP / 2 Byte ≈ 1 FLOP/Byte；而 GPU 的算力/带宽比通常在几十到上百 FLOP/Byte。算力大量闲置，时间被"把 W 从显存搬进来"这一件事决定。
2. **选项分析**：A 错，tensor core 与 batch 大小的关系是"利用率低"而不是"不允许用"；B 错，kernel 启动开销是微秒级，无法解释持续的低利用率；C 是错误归因，数值正确性与性能无关；D 正确，GEMV 的瓶颈是带宽。
3. **业务延伸**：GEMV 场景的优化方向是"减少搬运"（量化权重把 W 的字节数压小、提高 L2 命中率），而不是"提高 FLOPS"。反过来，batch 越大越接近 GEMM，此时才值得上 tensor core 和大 tile。

### 第 2 题
【题型：单选题】【难度：基础】
【题干】同一份权重矩阵，服务端要同时跑"单条长文本的流式解码"和"一次性 prompt 预填充（512 token）"。关于这两种负载的算子选择，正确的是？
【选项】
A. 预填充必须用 GEMV，因为 token 之间不能并行
B. 两者都应该用同一条 GEMM kernel，因为权重相同
C. 解码阶段（B=1）是 GEMV 型、访存受限；预填充（B=512）是 GEMM 型、可吃满 tensor core，通常走不同 kernel
D. 解码阶段比预填充更吃算力
【正确答案】C
【详细解析】
1. **核心原理**：同一个权重矩阵在两种 batch 下的算术强度天差地别。B=1 时每字节权重只换来约 1 次乘加；B=512 时同一份权重被复用 512 次，算术强度放大 512 倍，此时 compute-bound，值得用 tensor core 的大 tile GEMM。
2. **选项分析**：A 错，预填充的 token 维度天然可并行，正是 GEMM 的 N/M 维度；B 忽略了算术强度的巨大差异，用一条 kernel 必然有一端不最优；C 正确；D 错，解码阶段的绝对 FLOPs 反而小得多，只是"每 FLOP 摊到的带宽成本"高。
3. **业务延伸**：这也是为什么推理引擎会把 MMVQ（量化矩阵-向量）和 MMQ（量化矩阵-矩阵）做成两条路径，并按 batch 阈值切换。调优时先判断负载属于哪一类，再谈优化。

### 第 3 题
【题型：单选题】【难度：基础】
【题干】团队讨论一个算子优化的优先级。关于"算术强度（Arithmetic Intensity）"这一指标，正确的理解是？
【选项】
A. 算术强度 = 算力 ÷ 带宽，数值越大越好，与数据复用无关
B. 算术强度 = 每访问 1 字节数据所执行的浮点运算次数，它决定算子更接近 compute-bound 还是 memory-bound
C. 算术强度只与 kernel 的线程数有关
D. 算术强度高的算子一定比算术强度低的算子快
【正确答案】B
【详细解析】
1. **核心原理**：算术强度 = FLOPs / Bytes（对显存而言）。把它和硬件的"算力/带宽"比（roofline 的拐点）比较，低于拐点则受带宽限制，高于拐点则受算力限制。提高算术强度的唯一手段是"数据复用"：把数据搬到寄存器/共享内存后反复用。
2. **选项分析**：A 把两个概念混为一谈；B 正确；C 错，线程数只影响并行度，不改变数据被复用的次数；D 错，高算术强度也可能被其他瓶颈（延迟、指令发射、bank conflict）拖住。
3. **业务延伸**：调优时先算一笔账：这个算子每字节权重做了几次乘加？如果答案接近 1，就别指望提升 FLOPS，应该去压缩权重体积或增大 batch。

### 第 4 题
【题型：单选题】【难度：基础】
【题干】RoPE（旋转位置编码）对 Q、K 的每一对相邻维度施加一个与位置 m 相关的旋转。其数学本质是？
【选项】
A. 对向量做归一化，使其模长为 1
B. 把位置信息加到向量的每一个分量上（逐元素加法）
C. 把二维子空间 `(x_{2i}, x_{2i+1})` 按角度 `m·θ_i` 旋转，使两个向量的内积只依赖于它们的相对位置
D. 对向量做一次傅里叶变换并丢弃高频分量
【正确答案】C
【详细解析】
1. **核心原理**：对第 i 对维度，RoPE 用旋转矩阵 R(mθ_i) 作用于 (x_{2i}, x_{2i+1})。由于旋转矩阵正交，内积 `<R(mθ)q, R(nθ)k> = <q, R((n−m)θ)k>`，即注意力分数只取决于相对距离 n−m。这就是"相对位置编码"的实现方式。
2. **选项分析**：A 是归一化（LayerNorm 类操作），与位置无关；B 是绝对位置编码（可学习/正弦加法）的做法；C 正确；D 与 RoPE 无关。
3. **业务延伸**：RoPE 是"逐对旋转"，所以 head dim 必须是偶数；这也解释了为什么工程上会把 cos/sin 预先算成表（按位置和维度），推理时只做查表 + 乘加，避免每次重复算三角函数。

### 第 5 题
【题型：单选题】【难度：基础】
【题干】一个实现把 RoPE 同时施加到了 Q、K、V 三者上，结果模型输出明显变差。从原理上看，为什么 V 通常不加 RoPE？
【选项】
A. 因为注意力的位置信息只需要体现在"Q 与 K 的匹配分数"上；V 是加权求和的内容，旋转 V 会破坏内容语义
B. 因为 V 不需要参与 softmax，所以不能旋转
C. 因为 V 只有第一个 token 需要位置信息
D. 因为 V 的维度比 Q/K 小，不能做旋转
【正确答案】A
【详细解析】
1. **核心原理**：位置信息的作用是决定"query 应该关注哪个位置"。这个决策发生在 QK^T 这一步，所以只需对 Q、K 施加 RoPE。V 承载的是被聚合的内容，输出 O = Σ p_i · V_i，对 V 做旋转等于把内容本身按位置扭曲。
2. **选项分析**：A 正确；B 错，是否参与 softmax 与能否旋转无逻辑关系；C 错，位置信息是逐 token 的，不存在"只有第一个 token"；D 错，V 的维度可以任意。
3. **业务延伸**：写自定义 attention 算子时，RoPE 一般作为独立算子先作用在 Q、K 上，attention kernel 本身只看到"已编码位置"的 Q/K。这样 attention 内核无需感知位置逻辑，也方便和 KV cache 配合。

### 第 6 题
【题型：单选题】【难度：基础】
【题干】某模型把 LayerNorm 换成了 RMSNorm，训练和推理都更稳更快。二者的核心差异是？
【选项】
A. 两者完全相同，只是命名不同
B. LayerNorm 不包含可学习参数，RMSNorm 包含
C. RMSNorm 不减均值，只按均方根归一化；LayerNorm 同时减均值再除以标准差
D. RMSNorm 精度更高，LayerNorm 只能用于 FP32
【正确答案】C
【详细解析】
1. **核心原理**：LayerNorm: `y = (x − μ)/σ · γ + β`，其中 μ 是均值、σ 是标准差；RMSNorm: `y = x / sqrt(mean(x²) + ε) · γ`，省掉减均值，只做尺度归一化。减均值这一步需要额外的归约（多一次跨线程求和），RMSNorm 把它省掉了。
2. **选项分析**：A 错；B 错，两者通常都有可学习缩放 γ（LayerNorm 还常有 β）；C 正确；D 错，两者都可用半精度，RMSNorm 反而因为少一次归约而对数值更友好。
3. **业务延伸**：工程上 RMSNorm 的收益有两层：一是少一次块内归约（更少 shuffle/同步），二是语义上不强制零均值，对 FP16/BF16 更宽容。自研归一化算子时，如果发现收益不明显，先看是不是被归约和同步拖住了。

### 第 7 题
【题型：单选题】【难度：基础】
【题干】关于 Softmax 在实现时"先减去这一行的最大值"，下列说法正确的是？
【选项】
A. 减最大值只是为了把结果限制在 [0,1]，不影响数值稳定性
B. 减最大值会让结果变精确，因为它改变了 softmax 的定义
C. 减最大值是为了防止 `exp(x)` 在 x 很大时上溢成 inf，且数学上不改变 softmax 的结果
D. 只有当输入存在负数时才需要减最大值
【正确答案】C
【详细解析】
1. **核心原理**：`softmax(x)_i = exp(x_i)/Σexp(x_j)`。分子分母同乘 `exp(−m)`（m 为该行最大值）得 `exp(x_i − m)/Σexp(x_j − m)`，结果完全等价，但所有指数参数 ≤ 0，`exp` 值落在 (0,1]，不会上溢。FP16 的最大值约 65504，`exp(20)` 已经溢出，所以这一步在半精度下是必需而非可选。
2. **选项分析**：A 错，它恰恰是数值稳定性的关键手段，且不影响取值范围（本来就是 [0,1]）；B 错，数学上完全等价，不改变定义；C 正确；D 错，即使全为正数，只要数值偏大就会溢出。
3. **业务延伸**：在 FlashAttention 里这一步被推广成 online softmax：因为不能等整行算完，必须"边算边更新最大值并重标定已累加的结果"。理解"减最大值不改变结果"是理解 online softmax 重标定公式的前提。

### 第 8 题
【题型：单选题】【难度：基础】
【题干】某 FFN 层用 `SiLU(x) * gate` 做门控。关于 SiLU（Swish）函数的特性，正确的是？
【选项】
A. SiLU(x) = x·tanh(x)
B. SiLU(x) 是纯线性函数
C. SiLU(x) = max(0, x)，就是 ReLU
D. SiLU(x) = x·sigmoid(x)，在 x 很负时趋近 0，在 x 很大时趋近 x，平滑且非单调
【正确答案】D
【详细解析】
1. **核心原理**：SiLU(x) = x·σ(x)，σ 是 sigmoid。它在 x→−∞ 时 →0（负半轴有界），x→+∞ 时 →x（正半轴线性），且在 x≈−1.28 处取极小值，因此**非单调**。相比 ReLU 的硬拐点，SiLU 处处可导，梯度更平滑。
2. **选项分析**：A 是 GELU 的近似形式（`x·Φ(x)` 与 `x·tanh` 近似相关），不是 SiLU；B 错，明显非线性；C 是 ReLU；D 正确。
3. **业务延伸**：GLU 类算子（`act(x)·g`）里，SiLU 通常作用在 gate 那一半，与另一半逐元素相乘。工程上这个乘法常被融合进前一个 GEMM 的 epilogue，省掉一次中间张量的读写。

### 第 9 题
【题型：单选题】【难度：基础】
【题干】关于 GELU 与 SiLU 的对比，下列理解正确的是？
【选项】
A. GELU 与 SiLU 完全相同，只是名字不同
B. GELU 是分段线性函数，计算比 SiLU 便宜
C. SiLU 只在 FP32 下可用，GELU 只在 FP16 下可用
D. GELU 用标准正态分布的累积分布函数（或 tanh 近似）门控，SiLU 用 sigmoid 门控；两者都是平滑非单调的"自门控"激活
【正确答案】D
【详细解析】
1. **核心原理**：GELU(x) = x·Φ(x)（Φ 为标准正态 CDF），常用 tanh 近似；SiLU(x) = x·σ(x)。两者的共同结构是"用一条平滑的、值域 (0,1) 的曲线去门控 x 本身"，因此都是自门控、平滑、非单调。
2. **选项分析**：A 错，门控函数不同；B 错，GELU 含 tanh/erf，通常比 SiLU 更贵（所以很多实现用 tanh 近似或查表）；C 错，两者都能用半精度；D 正确。
3. **业务延伸**：精度上，GELU 的 tanh 近似在 FP16 下容易损失尾部分辨率，选择激活时既要看模型精度指标，也要看算子的指令开销。工程上常用一条"近似 + 修正"的公式在速度和精度间取舍。

### 第 10 题
【题型：单选题】【难度：基础】
【题干】Transformer 里几乎每层都有残差 `y = x + F(x)`。从算子实现角度看，残差 Add 的关键价值是？
【选项】
A. 它提供了恒等映射的梯度通路，使深层网络可训练；实现上是逐元素加法，几乎不增加计算量
B. 它改变了张量的形状，便于后续矩阵乘
C. 它提升了算力利用率，因为它把两个算子合并了
D. 它把数据从显存搬到共享内存，减少访存
【正确答案】A
【详细解析】
1. **核心原理**：残差连接的数学作用是让梯度通过恒等路径直接回传（∂y/∂x = I + ∂F/∂x），缓解梯度消失，这是深层可训练性的来源。计算上它是纯逐元素 add，FLOPs 极低。
2. **选项分析**：A 正确；B 错，逐元素加法不改变形状（除非配合广播）；C 错，它本身不改变算力利用率；D 错，它是计算而非搬运。
3. **业务延伸**：残差 Add 的真正工程成本在"访存"：读 x、读 F(x)、写 y，三次显存往返。因此实践中常把 Add 融合进前一个算子的输出（epilogue），或者与前一个逐元素算子（如激活）合并，减少一次读写。

### 第 11 题
【题型：单选题】【难度：基础】
【题干】注意力计算的正确流程是？
【选项】
A. V·K^T → softmax → 乘 Q
B. QK^T → 加 mask（可选）→ softmax → 乘 V
C. QK^T → 乘 V → softmax
D. softmax(QK^T) → 乘 V → 加 mask
【正确答案】B
【详细解析】
1. **核心原理**：S = QK^T（[Q_len, KV_len]）得到每个 query 对每个 key 的相似度；加 mask（causal / padding）把不可见位置置为 −∞；softmax 沿 KV 维度归一化成概率 P；O = P·V 得到加权内容。
2. **选项分析**：A 完全错位（用 V·K^T 无意义）；B 正确；C 顺序错，softmax 必须在乘 V 之前；D 顺序错，mask 必须在 softmax 之前（否则被 mask 的位置已经被计入概率）。
3. **业务延伸**：mask 必须在 softmax 之前，是因为 softmax 的分母是所有 exp 之和——把不可见位置置为 −∞ 后其 exp 为 0，才不参与归一化。FlashAttention 中 mask 在 online softmax 的每一步 tile 上施加，逻辑等价。

### 第 12 题
【题型：单选题】【难度：基础】
【题干】一个长上下文服务在 KV cache 达到 32K 时显存被 attention 中间矩阵撑爆。改用 FlashAttention 后显存从 O(n²) 降到 O(n)。其根本原因是？
【选项】
A. FlashAttention 跳过了 softmax 的计算
B. FlashAttention 把 QK^T、softmax、乘 V 融合成一个 kernel，不把完整的 [Q_len, KV_len] 分数/概率矩阵写回显存，只在片上保留 m、l、o 三个小状态
C. FlashAttention 用了更小的数据类型，把中间矩阵压缩了
D. FlashAttention 只计算注意力矩阵的上三角
【正确答案】B
【详细解析】
1. **核心原理**：朴素实现必须物化 S = QK^T（[Q_len, KV_len]）才能做 softmax，再物化 P 才能乘 V。FlashAttention 用 online softmax 把 KV 方向分块，每块算完立刻更新运行最大值 m、归一化因子 l 和输出累加 o（形状 [D_V]），块间不保留分数矩阵。显存只与 Q_len·D 和 KV_len·D 有关，即 O(n)。
2. **选项分析**：A 错，softmax 仍要做，只是改为在线形式；B 正确；C 错，它不是靠降精度省显存；D 错，causal 只是 mask 的一种，与显存复杂度无关。
3. **业务延伸**：注意"省显存"与"省算力"是两回事：FlashAttention 的 FLOPs 与朴素实现同量级（甚至略多，因为要重复做重标定），它省的是**显存容量和显存带宽**。长上下文下带宽才是瓶颈，所以整体更快。

### 第 13 题
【题型：单选题】【难度：基础】
【题干】FlashAttention 中 online softmax 的核心操作是：每处理一个新的 KV 块，若发现新的最大值 `m_new > m_old`，就要把之前累加的结果乘上一个系数。这个系数的含义是？
【选项】
A. `1 / l_old`，做归一化
B. `exp(m_old − m_new)`，把此前基于旧最大值归一化的累加结果，重标定到新最大值下
C. `sqrt(m_new)`，做尺度修正
D. `exp(m_new − m_old)`，把新块的结果放大
【正确答案】B
【详细解析】
1. **核心原理**：设旧状态为 (m_old, l_old, o_old)，其中 `l_old = Σexp(s − m_old)`、`o_old = Σexp(s − m_old)·V`。新块最大值更大时 m_new > m_old，需要把旧累加量按 `α = exp(m_old − m_new)` 缩小，因为原来以 m_old 为基准的 exp 值在新基准下都少了这个因子。然后 `l_new = α·l_old + Σexp(s_new − m_new)`，`o_new = α·o_old + Σexp(s_new − m_new)·V`。
2. **选项分析**：A 是最后输出归一化时用的（O = o/l），不是重标定系数；B 正确；C 无意义；D 方向反了，会让结果指数级放大。
3. **业务延伸**：`α` 的存在意味着每遇到一次更大的最大值就要重标定一次 o，所以 KV 顺序会影响重标定次数，但**不影响最终数学结果**（因为每次重标定都是等价的数学变换）。调试 online softmax 时，用"分块结果 == 一次性 softmax 结果"作为正确性判据。

### 第 14 题
【题型：单选题】【难度：基础】
【题干】一个新手把 FlashAttention 的分块大小（KV 方向 tile）设得非常大，以为"块越大越快"。结果性能反而下降。最可能的原因是？
【选项】
A. 块越大，需要同时驻留在共享内存/寄存器里的 K、V、分数 tile 越多，超出片上容量后要么降 occupancy、要么溢出到显存，延迟隐藏能力反而变差
B. 块太大导致 softmax 数学错误
C. 块大小必须是 2 的幂，否则 kernel 会拒绝执行
D. 块太大就不能用 mask
【正确答案】A
【详细解析】
1. **核心原理**：tile 大小受片上资源约束：K tile、V tile、Q tile、分数 tile 都要放在 shared memory 或寄存器里。tile 越大，shared memory 占用越多 → 每个 SM 能同时驻留的 block 越少（occupancy 下降），或者寄存器溢出（spill）。分块的意义是"让数据在片上被复用"，但复用窗口不能超过容量。

3. **业务延伸**：tile 大小是"复用收益 vs 占用代价"的权衡，通常由 head size、GQA ratio、GPU 架构共同决定，绝不是越大越好。调参时先看 occupancy 和 shared memory 用量，再看 stall 原因。

### 第 15 题
【题型：单选题】【难度：基础】
【题干】CUDA 用 grid / block / warp 三级组织线程。关于这三级的核心目的，正确的是？
【选项】
A. grid 决定精度，block 决定显存容量，warp 决定数据类型
B. grid 把整个问题切成可独立调度的单位，block 是能共享 shared memory 并同步的协作单位，warp 是硬件实际以 SIMT 方式执行的 32 线程单位
C. warp 是软件概念，硬件按 block 执行
D. 三级只是命名不同，硬件只认单个线程
【正确答案】B
【详细解析】
1. **核心原理**：grid 是最外层并行度，block 之间不能共享片上内存也不能直接同步（只能靠全局内存/原子操作）；block 内线程可以共享 shared memory 并用 `__syncthreads()` 同步，这是"数据复用 + 协作归约"的基础；warp 是 32 个线程，硬件以 warp 为单位取指、发射，同 warp 内线程执行同一条指令（SIMT）。
2. **选项分析**：A 错，三级与精度/容量/类型无关；B 正确；C 错，warp 恰恰是硬件执行单位；D 错，硬件确实按 warp 调度。
3. **业务延伸**：这三级直接决定算法设计：需要"数据复用"就放进 block（shared memory），需要"跨块合并"就只能在全局内存做（如 split-K 的部分和），而 warp 内通信要用 shuffle 而不是 shared memory。

### 第 16 题
【题型：单选题】【难度：基础】
【题干】为什么一个 block 内的线程"要能共享数据"这件事如此重要？
【选项】
A. 因为共享数据可以减少每个线程的寄存器用量
B. 因为同一个 tile 的数据被 block 内多个线程反复使用（如 K/V tile 被多个 query 行复用），共享内存让"一次从显存加载、多次片上访问"成为可能，显著提高算术强度
C. 因为共享数据能让 block 之间的线程通信
D. 因为共享数据可以绕过 L2 直接访问显存
【正确答案】B
【详细解析】
1. **核心原理**：显存访问是延迟高、带宽有限的资源。把 tile 数据搬到 shared memory 后，块内所有线程都能以极低延迟反复读取，把"每个元素读一次"变成"加载一次、使用多次"。这正是 GEMM/attention 分块能大幅提速的根本。
2. **选项分析**：A 错，shared memory 不减少寄存器压力（反而占用片上资源）；B 正确；C 错，block 之间无法共享 shared memory；D 错，共享内存是片上存储，不涉及绕过。
3. **业务延伸**：设计算子时先问"这份数据会被读几次"：读一次就丢的（纯逐元素）不需要 shared memory；被多个线程/多次迭代复用的（tile、权重、K/V）才值得搬进来。搬进来的代价是 occupancy 下降，需要权衡。

### 第 17 题
【题型：单选题】【难度：基础】
【题干】在一个需要做 32 元素归约（如求行最大值）的 kernel 里，用 warp shuffle 比用 shared memory 更快。原因是？
【选项】
A. shuffle 是 warp 内的寄存器级交换，不需要写 shared memory、不需要 `__syncthreads()`；而 shared 归约要经历"写 shared → 同步 → 读 shared"多轮往返
B. shared memory 归约必须串行执行
C. shuffle 能自动使用 tensor core
D. shuffle 使用了更高精度的数据类型
【正确答案】A
【详细解析】
1. **核心原理**：`__shfl_xor_sync` 等 shuffle 指令直接在寄存器之间传递数据，warp 内同步由硬件隐式保证，一轮归约只需 log2(32)=5 步、零次 shared 往返、零次 barrier。shared 归约每一步都要"写 → `__syncthreads()` → 读"，屏障本身还有延迟。

### 第 18 题
【题型：单选题】【难度：基础】
【题干】关于 occupancy（占用率），正确的理解是？
【选项】
A. occupancy 只由 block 大小决定
B. occupancy 是显存带宽利用率
C. occupancy 是每个 SM 上活跃 warp 数与该 SM 支持上限的比值；它衡量"有多少并行工作可用来隐藏延迟"，但过高会挤压寄存器/共享内存，可能反而降低性能
D. occupancy 越高，kernel 一定越快，应该把它拉满
【正确答案】C
【详细解析】
1. **核心原理**：SM 靠"切换 warp"来隐藏内存延迟和指令延迟，所以需要足够多的活跃 warp。但每个 warp 都要占寄存器、每个 block 要占 shared memory，资源总量固定，因此 occupancy 与"每个线程可用资源"此消彼长。有时故意降低 occupancy、给每个线程更多寄存器和更高 ILP，反而更快。
2. **选项分析**：A 错，还受寄存器数、shared memory 用量、架构上限共同约束；B 错，occupancy 与带宽是不同维度；C 正确；D 错，这是最常见的误解。
3. **业务延伸**：调优口诀是"先看瓶颈"：如果是延迟受限（访存稀疏、依赖长），提高 occupancy 有用；如果是带宽或算力受限，提高 occupancy 无用甚至有害。用 profiler 看 achieved occupancy 与 stall reason，而不是盲目调 block size。

### 第 19 题
【题型：单选题】【难度：基础】
【题干】关于 GPU 存储层级的容量与带宽量级，正确的排序是（从最快最小到最慢最大）？
【选项】
A. 共享内存 → 寄存器 → 全局显存 → L2
B. 寄存器 → 共享内存/L1 → L2 → 全局显存，且容量依次增大、带宽依次降低
C. L1 → 寄存器 → 共享内存 → 全局显存
D. 全局显存 → L2 → 共享内存/L1 → 寄存器
【正确答案】B
【详细解析】
1. **核心原理**：寄存器最快（每线程私有、~百 KB 级每 SM）；共享内存/L1 次之（每 SM ~百 KB 级，可编程管理）；L2 是芯片级共享（几 MB 到几十 MB）；全局显存最慢最大（GB 级）。带宽从高到低、容量从小到大是一致的层次结构。

### 第 21 题
【题型：单选题】【难度：基础】
【题干】一个矩阵转置/分块 kernel 在某个 GPU 上比预期慢了一倍。用 profiler 发现 shared memory 的访问被拆成了很多次串行事务。最可能的原因是？
【选项】
A. 数据类型不是 32 位
B. 显存容量不足
C. 线程数太少，GPU 空闲
D. 出现了 bank conflict：同一 warp 内多个线程访问了同一个 bank 的不同地址，硬件把它们串行化
【正确答案】D
【详细解析】
1. **核心原理**：shared memory 被划分为 32 个 bank，每个 bank 每周期只能服务一个地址。若一个 warp 内的线程访问落在同一 bank 的不同地址，硬件必须把这些访问拆成多轮（最坏 32 路冲突 → 32 倍慢）。典型触发场景是按列访问行主序的二维 tile（转置、按列归约）。
2. **选项分析**：A 错，32 位对齐反而有利于避免冲突；B 显存容量与 shared 事务数无关；C 与"串行事务"现象不符；D 正确。
3. **业务延伸**：排查手段是让 profiler 看 shared memory 的 conflict 计数，或做"波前分析"：把 warp 内 32 个线程的地址按 bank 列出来，看有没有重复。注意：如果所有线程读**同一地址**（broadcast），硬件会广播，不算冲突。

### 第 22 题
【题型：单选题】【难度：基础】
【题干】常见的"给二维 shared memory tile 的列方向加一个 padding（如宽度 +1）"能消除 bank conflict，其原理是？
【选项】
A. padding 让数据自动对齐到 128 字节
B. padding 增加了容量，让更多数据能放下
C. padding 把 shared memory 换成了寄存器
D. padding 改变了行与行之间的地址步长，使按列访问时同一 warp 的线程落在不同的 bank 上，把冲突访问打散
【正确答案】D
【详细解析】
1. **核心原理**：设 tile 宽度为 W、按列访问时相邻行同列的地址差为 W 个元素。若 W 是 32 的倍数，同一列上不同行的元素会落在同一个 bank（地址差是 32 的整数倍）。把宽度改成 W+1 后，地址差变成 W+1，与 32 互素，于是相邻行的同列元素落在相邻 bank 上，冲突消失。
2. **选项分析**：A 错，对齐不是目的；B 错，padding 是牺牲一点容量换访问模式；C 错；D 正确。
3. **业务延伸**：padding 是最经典的"用空间换访问效率"手段，代价是容量浪费（W+1 行会有 1 列空洞）和地址计算略复杂。替代方案有 swizzle（地址异或重排）和改变数据布局，选择取决于 tile 尺寸和访问模式。

### 第 24 题
【题型：单选题】【难度：基础】
【题干】把 `GEMM → 逐元素激活` 两个 kernel 融合成一个，最直接的收益是？
【选项】
A. 让 tensor core 更容易被触发
B. 减少了中间张量写回显存再读出来的往返，并省掉一次 kernel 启动开销
C. 减少了浮点运算次数，FLOPs 直接减半
D. 提高了数据精度
【正确答案】B
【详细解析】
1. **核心原理**：不融合时，第一个 kernel 把 GEMM 结果写回显存（写 N×M 个元素），第二个 kernel 再读回来（读同样多）做激活、再写出。融合后这个中间结果只存在于寄存器/共享内存，直接原地做激活再写最终结果，省掉"写 + 读"两次显存往返。同时省掉一次 kernel launch 及其调度开销。

3. **业务延伸**：融合的收益取决于中间张量大小与算子计算量之比。中间张量越大、算子越"轻"，融合收益越明显（典型是 GEMM + bias/激活/GLU）。反之，两个都很重的 kernel 融合收益有限。

### 第 25 题
【题型：单选题】【难度：基础】
【题干】为什么 `GEMM + bias` 的融合几乎是"白捡"的收益？
【选项】
A. 因为融合后可以跳过矩阵乘
B. 因为 bias 必须放在 shared memory 里才能算
C. 因为 bias 加法可以在 GEMM 的结果从累加器写出的那一刻顺手完成，不需要额外的显存往返
D. 因为 bias 会改变 GEMM 的数学定义，减少计算量
【正确答案】C
【详细解析】

### 第 26 题
【题型：单选题】【难度：基础】
【题干】某框架宣称支持 `GEMM + GLU` 融合，但实测发现没有生效，性能与两个独立 kernel 相同。从原理上看，融合失效的直接后果是？
【选项】
A. 数值结果错误
B. 中间张量被完整写回显存又被读回，多了一轮显存往返和一次 kernel 启动，带宽和延迟都没有节省
C. tensor core 被禁用
D. 显存容量溢出
【正确答案】B
【详细解析】
1. **核心原理**：融合的全部收益就是"省中间张量的写读 + 省一次启动"。失效后收益归零，回到两个 kernel 的行为：第一个把中间结果写显存，第二个读回来做门控。性能自然与未融合一致。
2. **选项分析**：A 错，融合与否不影响数学正确性（前提是原实现正确）；B 正确；C 错，tensor core 是否使用由数据类型/形状决定；D 错，显存占用略增但通常不溢出。
3. **业务延伸**：融合"静默不生效"是工程上高频坑：常见原因是张量布局（stride）不满足融合路径的要求、类型不在支持列表、形状触发 fallback。排查方法是看实际执行的 kernel 数量与名字，而不是看框架的"支持融合"声明。

### 第 27 题
【题型：单选题】【难度：基础】
【题干】一个自定义算子只处理了连续（contiguous）张量，上线后在某个模型里结果错乱。最可能的原因是？
【选项】
A. 上游张量是某个更大张量的 view（或转置结果），stride 不连续；kernel 按连续布局算索引，读到了错误的元素
B. 精度设置不对
C. 线程数不够
D. GPU 坏了
【正确答案】A
【详细解析】
1. **核心原理**：GGML 张量由 `ne[]`（各维大小）和 `nb[]`（各维字节步长）描述，同一个逻辑张量可以有不同物理布局。view、permute、transpose 都会产生 stride 不连续的张量。若 kernel 假设"第 i 行紧接第 i−1 行"，而实际 stride 更大，就会读错位置。
2. **选项分析**：A 正确；B 精度问题表现为数值偏差而非错乱；C 线程数不足会导致部分元素未计算，但这里是"结果错乱"；D 是玩笑。
3. **业务延伸**：两种处理方式：一是在 host 端断言/检查连续性，不满足就 `contiguous` 拷贝一份；二是让 kernel 显式读取 nb[] 做跨步寻址。前者实现简单但有拷贝开销，后者零拷贝但要求 kernel 支持任意 stride。上线前务必用"非连续输入"做一次测试。

### 第 28 题
【题型：单选题】【难度：基础】
【题干】自定义算子接入后，如何验证 CPU/GPU 结果一致最靠谱？
【选项】
A. 只要不崩溃就算通过
B. 对比两次 GPU 运行的结果是否相同
C. 用同一份输入分别跑 CPU 参考实现和 GPU kernel，逐元素比对，统计最大绝对/相对误差并设定合理容差（半精度容差应放宽）
D. 只看输出的前 10 个元素
【正确答案】C
【详细解析】
1. **核心原理**：CPU 与 GPU 的累加顺序、是否使用 FMA、是否半精度累加都不同，结果不会逐位相同，但应在合理误差内。验证必须覆盖全元素并区分"误差"与"错误"：若误差随规模线性增长可能是精度问题，若个别元素完全错则多半是索引/边界 bug。
2. **选项分析**：A 太低标准；B 只能验证确定性，不能验证正确性；C 正确；D 抽样会漏掉边界元素（尾块、越界），而边界 bug 恰恰最常见。
3. **业务延伸**：测试矩阵要覆盖：非连续输入、尾块尺寸（如长度 1/255/256/257）、多 batch、边界维度、极端数值。半精度算子的容差通常取相对 1e-2 量级、FP32 取 1e-4~1e-5 量级，具体看累加长度。

### 第 29 题
【题型：单选题】【难度：基础】
【题干】一个算子需要对形状 `[4, 8, 16]` 和 `[8, 1]` 的张量做加法（广播）。下列判断正确的是？
【选项】
A. 广播合法，只要从最后一维开始对齐，长度为 1 的维度可以扩展到另一边的长度
B. 广播非法，因为必须形状完全相同
C. 广播合法，因为两个张量的元素总数相同
D. 广播非法，因为维度数不同
【正确答案】A
【详细解析】
1. **核心原理**：广播规则是"从最后一维往前逐维对齐，每维要么相等，要么其中一个是 1"。`[4,8,16]` 与 `[8,1]` 对齐后是 `[4,8,16]` vs `[1,8,1]`，每维都满足，结果形状 `[4,8,16]`。实现上把长度为 1 的维度步长视作 0，于是索引重复。
2. **选项分析**：A 正确；B 错，太严格；C 错，元素数相同不是广播条件；D 错，缺省维度视为 1。
3. **业务延伸**：广播的实现要点是"stride=0 表示这一维不前进"。注意广播会让被广播维度的数据被反复读取（如 bias 每行读一次），这类算子通常是访存受限，优化重点是把广播数据放进寄存器/共享内存，避免重复走显存。

### 第 30 题
【题型：单选题】【难度：基础】
【题干】什么情况下"必须"对大张量做分片计算？
【选项】
A. 只要张量超过 100 万元素就必须分片
B. 当单个张量或其计算结果超出单卡显存容量，或需要跨设备并行以利用多卡算力时
C. 只有 FP16 张量需要分片
D. 只要想提高性能就必须分片

【详细解析】

### 第 31 题
【题型：单选题】【难度：基础】
【题干】一个 FP32 权重、FP32 激活的 GEMM 跑在支持 Tensor Core 的卡上，却始终没触发 tensor core。最直接的原因是？
【选项】
A. Tensor Core 做的是低精度（FP16/BF16/TF32/INT8 等）矩阵乘累加，FP32 输入需要显式转换或走 TF32 路径才能被硬件矩阵指令使用
B. Tensor Core 只能处理 batch=1
C. 张量的形状不是方阵
D. 必须显式调用 cuDNN
【正确答案】A
【详细解析】
1. **核心原理**：Tensor Core 是面向"小矩阵乘加"的专用单元，输入通常是半精度/低精度，累加器可以是 FP32。纯 FP32 的乘加不由 tensor core 完成。要利用它，要么把输入转成 FP16/BF16，要么使用 TF32（截断尾数的 FP32 近似）——后者精度略降但吞吐显著提升。

3. **业务延伸**：选择精度路线时要权衡：BF16 动态范围大但尾数少、FP16 尾数多但范围小、TF32 精度接近 FP32 但吞吐低于半精度。模型对精度敏感时，可只对部分层降精度。

【选项】
A. Tensor Core 的矩阵指令要求参与维度对齐到特定粒度（如 8/16），K 不对齐时无法走快速路径，只能退化到普通 FMA 或做补零

【选项】
A. 因为此时 M 维（query 数）只有 1，无法填满矩阵指令要求的最小 tile，tensor core 的并行度用不起来；反而向量式实现在带宽利用和启动开销上更划算

【选项】
A. 自动消除 bank conflict
B. 让数据以更高精度加载
C. 让"从显存加载到共享内存"这一步不占用线程的寄存器、不需要等数据到齐才能继续执行，从而把加载与计算重叠，隐藏访存延迟

3. **业务延伸**：异步拷贝的收益在"访存延迟高、计算可重叠"的场景最明显，典型就是 attention 和 GEMM 的 K 循环。使用时要保证共享内存有双缓冲（ping-pong）空间，否则无处存放预取数据，流水线就断了。

【选项】
A. 提高 kernel 的时钟频率
B. 后一个 kernel 可以在前一个 kernel 还没完全结束时就开始启动（提前读取 launch 依赖、初始化），但在真正读取前一个 kernel 产出的数据之前必须等待其完成
C. 让两个 kernel 跑在不同的 GPU 上

A. 任何场景，因为跳过计算总是更快

### 第 39 题
【题型：单选题】【难度：基础】
【题干】长上下文推理中，随着 KV 长度增长，attention 的时间占比会先升后趋于"访存受限"。出现这个拐点的原因是？
【选项】
A. GPU 会在大 KV 时自动降频
B. KV 长度增加使 K/V 的读取量线性增长，而每个 query 的计算量也线性增长，但 KV cache 无法全部放进片上缓存，必须反复从显存读取，于是带宽成为约束；同时超出 L2 容量后命中率下降
C. 长上下文时 head 数会减少
D. KV 太长时 softmax 无法计算
【正确答案】B
【详细解析】
1. **核心原理**：attention 的计算量随 KV 长度线性增长，K/V 的读取量也线性增长。短 KV 时 K/V 能驻留 L2，读取代价低，瓶颈可能在计算；KV 变长后工作集超过 L2，每次都要走显存，而显存的算力/带宽比远低于 L2，于是转为带宽受限。
2. **选项分析**：A 错，无此机制；B 正确；C 错；D 错，softmax 与长度无关（除非数值问题）。
3. **业务延伸**：应对手段：KV cache 量化（减小每字节成本）、分块 + 合理的 block 调度顺序提高 L2 命中、稀疏/滑窗注意力减少可见 KV。评估长上下文性能必须报告"KV 长度 × batch × 精度"三维矩阵，单点测试会误导。

【选项】
A. batch 大小（每个权重被复用的次数）
B. 张量在显存中的布局是否连续、是否合并访存

A. 一定提高数值精度
B. 省掉中间张量的"写回显存 + 再读出"两次显存往返
C. 让中间结果留在寄存器/共享内存，缩短数据生命周期

【选项】
A. 把 tile 宽度加 1 后按列访问

E. 可以做浮点数的任意精度累加
【正确答案】ACD
【详细解析】
1. **核心原理**：shuffle 是寄存器级、warp 内隐式同步的操作，因此省屏障（C）、省往返（D）、省共享内存（A）。
2. **选项分析**：B 错，shuffle 只在 warp 内有效，跨 block 只能用全局内存/原子操作；E 错，shuffle 传递的是同类型数据，不改变精度。
3. **业务延伸**：标准的两级归约是"warp 内 shuffle → 每个 warp 的 leader 写 shared → 第一个 warp 读 shared 再 shuffle"。只做 warp 内归约而不处理跨 warp 部分，是自定义归约算子的常见 bug。

### 第 61 题
【题型：单选题】【难度：进阶】
【题干】在 FlashAttention 中把 query tile 的宽度（一个 block 同时处理的 query 行数/head 数）调大，GQA ratio 为 8 时收益明显，但 ratio 为 1 时反而变慢。原理是？
【选项】
A. tile 宽度必须等于 GQA ratio
B. tile 宽度越大，每个 K/V tile 被复用的次数越多，算术强度越高；但宽度增大同时占用更多寄存器和共享内存，ratio 低时复用收益不足，反被资源压力拖累
C. ratio 为 1 时 softmax 无法分块
D. tile 宽度只影响线程数，不影响性能
【正确答案】B
【详细解析】
1. **核心原理**：宽 tile 的本质是"一次加载 K/V，服务更多 query 行"。GQA ratio 高时，同一 K/V 天然被多个 Q head 共享，宽 tile 顺水推舟；ratio=1 时每个 Q head 需要自己的 K/V，宽 tile 只是把更多 Q 行塞进同一个 block，K/V 复用次数没有增加，而寄存器/shared 占用上升导致 occupancy 下降。
2. **选项分析**：A 错，二者是独立参数，只是存在"协同收益"；B 正确；C 错，分块与 ratio 无关；D 错。
3. **业务延伸**：调 tile 宽度的经验法则是"先看 ratio，再看 head dim"。ratio ≥ 2 且 head dim 较大时宽 tile 通常有收益；ratio=1 时优先保证 occupancy。上线前用 profiler 对比不同宽度下的 tensor core 利用率与 stall 原因。

### 第 64 题
【题型：单选题】【难度：进阶】
【题干】online softmax 中每次遇到更大的最大值就重标定已累加的输出 o。为什么这样做不会改变最终结果？
【选项】
A. 因为重标定是近似操作，误差可以忽略
B. 因为最终会除以 l，把误差抵消了
C. 因为 `o_new = α·o_old + Σexp(s−m_new)·V` 与"从头用新最大值重算"在数学上完全等价，α 只是把旧累加量的基准从 m_old 换算到 m_new

【正确答案】C

【题干】有人说"FlashAttention 之所以快，是因为它把注意力的计算复杂度从 O(n²) 降到了 O(n)"。这个说法错在哪？
【选项】
A. 错在 FlashAttention 反而增加了计算量
B. 错在它其实没有变快
C. 完全正确，没有错
D. 计算量仍是 O(n²)（每个 query 都要与所有 KV 做点积），降低的是**显存占用与显存访问量**——中间分数矩阵不再物化，因此从 O(n²) 显存降到 O(n)

【正确答案】A
【详细解析】
1. **核心原理**：向量化加载把"每元素一条指令"变成"每 4 个元素一条指令"，减少了指令数（对访存密集算子，指令发射常常是瓶颈之一）；并且 128 位对齐访问在硬件层面更容易形成高效的合并事务。
2. **选项分析**：A 正确；B 错，数据量没变；C 错；D 错，向量化不改变存储位置。
3. **业务延伸**：向量化的前提是地址对齐（16 字节）和连续。非连续张量（stride 不规则）或尾部元素需要退化为标量处理，这就是"尾块"处理代码的来源。实现时应把主体走向量路径、尾部走标量路径。

### 第 69 题
【题型：单选题】【难度：进阶】
【题干】一个 kernel 里 warp 内 32 个线程依次访问 `data[base + tid]` 时性能很好，改成 `data[base + tid*stride]`（stride 较大）后带宽利用率暴跌。原因是？
【选项】
A. 合并访存被破坏：硬件希望一个 warp 的访问落在一段连续地址上以便合并成少数宽事务，跨步访问会退化成每线程独立事务
B. 地址计算错误
C. stride 太大会导致 bank conflict
D. 编译器无法优化
【正确答案】A
【详细解析】
1. **核心原理**：显存事务以固定粒度（如 32/64/128 字节）为单位。若一个 warp 的 32 个线程访问连续地址，可合并成少数几个事务；若地址分散，硬件要发出大量事务，有效带宽利用率骤降。
2. **选项分析**：A 正确；B 错，结果正确只是慢；C 错，bank conflict 是共享内存的概念；D 错，这是访存模式问题而非编译问题。
3. **业务延伸**：矩阵按行/列访问的差异（行主序按列读）就是典型。解决办法是用共享内存做转置缓冲，或者调整线程到数据的映射（让 tid 对应最快的维度）。这是 attention 中 K/V 加载布局设计的关键考量。

### 第 70 题
【题型：单选题】【难度：进阶】
【题干】用共享内存做矩阵转置时，把 tile 声明为 `[32][33]` 而不是 `[32][32]`，性能提升明显。原理是？
【选项】
A. 减少了共享内存占用
B. 多出来的 1 列可以存额外的数据
C. 33 是奇数，硬件对奇数更友好
D. 33 与 32 互素，使"按列读"时同一 warp 内相邻行的元素落在不同 bank 上，消除了 bank conflict
【正确答案】D
【详细解析】
1. **核心原理**：bank 索引 = 地址 mod 32。tile 宽度为 32 时，同一列相邻两行地址差 32 → 同 bank → 冲突。宽度改为 33 后地址差为 33，与 32 互素，相邻行落在相邻 bank，冲突消除。
2. **选项分析**：A 错，反而多占一点；B 错，那一列是空洞；C 错，无此规律；D 正确。
3. **业务延伸**：转置缓冲是 padding 的经典应用。等价手段还有"地址异或 swizzle"，它不浪费容量但地址计算更复杂。选择时看 tile 形状与访问模式，并实测冲突计数。

### 第 71 题
【题型：单选题】【难度：进阶】
【题干】一个 GEMM kernel 为了容纳更大的 tile 把每线程寄存器需求推高，编译器报告出现了大量 spill。最直接的性能后果是？
【选项】
A. 寄存器不够用的变量被放到本地内存（本质是显存），每次访问都要走显存，延迟与带宽代价远高于寄存器，且会额外产生访存流量
B. 自动切换到共享内存，性能不受影响
C. 自动降低精度
D. 结果错误
【正确答案】A
【详细解析】
1. **核心原理**：寄存器是每线程私有的最快存储。当需求超过上限，编译器把部分变量"溢出"到 local memory（物理上在显存，走 L1/L2 缓存）。这既增加访存流量，又引入长延迟。
2. **选项分析**：A 正确；B 错，溢出目标是 local memory 而不是 shared；C 错；D 错，结果通常仍正确。
3. **业务延伸**：tile 大小与寄存器预算是硬约束。调优时用 `__launch_bounds__` 或编译选项限制寄存器数，观察是否出现 spill；若出现，应缩小 tile 或减少每线程工作量。这是"tile 不是越大越好"的另一面。

### 第 72 题
【题型：单选题】【难度：进阶】
【题干】一个 kernel 的 occupancy 从 25% 提到 75%，性能反而下降。最合理的解释是？
【选项】
A. 提高 occupancy 的代价通常是限制每线程寄存器数或缩小 tile，导致指令级并行（ILP）下降、更多 spill 或更频繁的同步，反而无法隐藏延迟
B. occupancy 统计错误
C. occupancy 与性能无关
D. 只有 occupancy 到 100% 才会变快
【正确答案】A
【详细解析】
1. **核心原理**：隐藏延迟有两条路：多放 warp（TLP，靠 occupancy）和让每个线程有更多独立指令（ILP）。二者争抢同一份寄存器资源。为了塞下更多 warp 而限制寄存器，会让每个线程的可用独立工作变少，访存延迟暴露。
2. **选项分析**：A 正确；B 错；C 错，它是重要指标之一；D 错，很多高性能 kernel 的 occupancy 只有 25%~50%。
3. **业务延伸**：正确的调优姿势是"先定位瓶颈再调 occupancy"：如果 stall 主要来自访存延迟且 ILP 已足够，提高 occupancy 有效；如果 stall 来自指令依赖或屏障，提高 occupancy 帮助有限。不要把它当唯一目标。

### 第 73 题
【题型：单选题】【难度：进阶】
【题干】一个 kernel 的共享内存占用很大，导致每个 SM 只能驻留 1 个 block。若该 block 在某个阶段需要等待共享内存写入完成，会发生什么？
【选项】
A. 硬件会自动复制 block
B. 硬件会自动缩小共享内存占用
C. 性能不受影响，因为共享内存很快
D. 没有其他 block 可切换，SM 只能空转等待，延迟无法被隐藏
【正确答案】D
【详细解析】
1. **核心原理**：warp 调度的意义在于"一个 warp 等待时切换到另一个 warp"。若每个 SM 只有 1 个 block、warp 数很少，可切换的候选不足，任何等待（共享内存延迟、屏障、访存）都直接暴露成空闲周期。
2. **选项分析**：A、B 都是硬件不存在的机制；C 错，共享内存虽快但仍有延迟，且屏障等待是同步点；D 正确。
3. **业务延伸**：这解释了"大 tile 换低 occupancy"的取舍逻辑：大 tile 提高复用，但也可能让 SM 失去隐藏延迟的能力。折中手段包括减小 tile、拆分缓冲、或增加每线程工作量（ILP）来补偿。

### 第 74 题
【题型：单选题】【难度：进阶】
【题干】在 GEMV 型算子里，同一份权重会被很多不同的 token 使用（多次 decode）。L2 cache 在这里的价值是？
【选项】
A. 提高张量核利用率
B. 存储 softmax 的中间结果
C. 把频繁复用的权重留在芯片级缓存里，使重复读取不必每次都走显存，从而缓解带宽瓶颈

### 第 75 题
【题型：单选题】【难度：进阶】
【题干】某 GEMM 在 K 维非常大、但 M/N 维较小（如 M=256, N=256, K=16384）时，SM 利用率偏低。split-K（沿 K 维切分）为什么能改善？
【选项】
A. 减少显存占用
B. 减少总 FLOPs
C. 把原本数量不足的并行工作拆成更多块，让更多 SM 有活干，最后再用归约把各部分和相加
D. 提高数据精度
【正确答案】C
【详细解析】
1. **核心原理**：并行度不足时（可切出的 M×N tile 数少于 SM 数），大量 SM 空闲。沿 K 维切分可以把同一输出 tile 的计算拆给多个 block，各自算部分和，再归并。总 FLOPs 不变（甚至因归约略增），但并行度提升、尾部效应减少。
2. **选项分析**：A 错；B 错；C 正确；D 错。

### 第 76 题
【题型：单选题】【难度：进阶】

【选项】
A. 小矩阵乘的数学更复杂
B. 小矩阵乘无法用半精度
C. 小规模下可拆出的并行 tile 数不足、每个 tile 的 K 循环太短，难以摊薄加载与启动开销，也难填满流水线

### 第 77 题
【题型：单选题】【难度：进阶】
【题干】用 roofline 思路判断一个算子该往哪个方向优化。若算子的算术强度低于硬件"算力/带宽"比，正确的结论是？
【选项】
A. 应该增加线程数
B. 处于带宽受限区，优化方向是减少访存字节数（量化、提高复用、改善访存模式），单纯提高 FLOPS 无收益

D. 应该提高精度
【正确答案】B

### 第 80 题
【题型：单选题】【难度：进阶】

【选项】
A. 只有半精度会变，FP32 逐位相同
B. 数学上等价，不改变定义；但融合可能改变累加/归约的顺序与中间精度，从而产生细微的舍入差异，通常远小于容差

### 第 83 题

【题干】一个算子对非连续输入（stride 不规则）的处理是"先拷贝成连续张量再计算"。这个策略的适用边界是？

A. 拷贝会改变数值结果
B. 当拷贝的数据量相对计算量较小、且拷贝本身能合并访存时才划算；若张量很大且算子本身很轻，拷贝的代价可能超过收益，此时应让 kernel 直接支持跨步寻址

### 第 84 题

A. 半精度没有加法
B. 半精度乘法更慢
C. FP16 只有约 10 位尾数，长序列累加时舍入误差不断累积；同时部分和可能超过 FP16 最大值（约 65504）而上溢成 Inf

B. ALiBi 会改变 head dim

### 第 91 题
【题型：单选题】【难度：进阶】
【题干】自回归解码时，每生成一个 token 只需为新 token 计算一次 query，但要与全部 KV cache 做注意力。这样做的数学依据是？
【选项】
A. 因为旧 token 的 Q 已经算过，可以复用
B. 因为旧 token 的注意力结果已经固定，可以直接复用；新 token 的注意力只依赖自己作为 query 与所有历史 key 的匹配
C. 因为 KV cache 只保存了最后一个 token
D. 因为 causal mask 让新 token 看不到自己
【正确答案】B
【详细解析】
1. **核心原理**：因果注意力下，第 t 个 token 的输出只依赖位置 ≤ t 的 K/V。已生成 token 的输出不会因为新 token 而改变（新 token 只影响未来），因此无需重算；而新 token 作为 query 必须与全部历史 K/V 计算分数。KV cache 正是为此保存所有历史的 K/V。

### 第 98 题

【题干】某自定义算子对张量要求"每行起始地址按 16 字节对齐"，否则走慢路径。这条约束的来源是？
【选项】
A. 编译器要求
B. 向量化加载/存储（如一次读 16 字节）要求地址满足对齐，才能用宽事务；不满足时只能退化为更窄的访问，吞吐下降
C. 为了美观
D. 显存控制器要求
【正确答案】B
【详细解析】
1. **核心原理**：宽向量指令（128 位）要求地址 16 字节对齐，否则硬件无法用单条指令完成，或需要拆成多次访问。这是"对齐换吞吐"的硬件约束。
2. **选项分析**：A 错（是硬件约束而非编译器）；B 正确；C 错；D 错。
3. **业务延伸**：这解释了为什么很多实现要求 stride 是 16 的倍数、为什么在分配时做 128 字节对齐。违反对齐不会算错（如果实现里有慢路径），但会显著变慢——属于"静默性能退化"，必须在上线前的性能回归里覆盖。

### 第 99 题
【题型：单选题】【难度：进阶】
【题干】同一段归约逻辑，在 CPU 上顺序累加、在 GPU 上树形并行累加，结果出现 ulp 级差异。定位与验收的正确做法是？
【选项】
A. 把 GPU 结果强制四舍五入到 CPU 结果
B. 认为 GPU 有 bug，要求逐位一致
C. 忽略差异，不设容差
D. 认识到浮点加法不满足结合律，不同归约顺序必然产生舍入差异；验收应按规模设定相对/绝对容差，并确认差异不随规模爆炸增长
【正确答案】D
【详细解析】
1. **核心原理**：`(a+b)+c ≠ a+(b+c)` 在浮点下普遍成立。GPU 的树形归约、FMA 融合、FP32 累加器都会改变舍入路径。合理的验收标准是"误差在容差内，且随累加长度呈可预期的缓慢增长"。
2. **选项分析**：A 错；B 错；C 错（不设容差会导致无法验收）；D 正确。
3. **业务延伸**：如果误差随规模快速增长或出现个别元素完全错误，就不是舍入问题，而是 bug（索引、边界、mask 位置）。定位方法是缩小规模逐步复现，并检查"误差是否集中在特定位置"（如第一行/最后一行/尾块）。

B. 没有收益

### 第 102 题
【题型：单选题】【难度：进阶】
【题干】实现"预取下一块 K/V + 计算当前块"的软件流水线时，第一轮迭代通常没有重叠效果。原因是？
【选项】
A. 第一轮还没有"下一块"可以预取，必须先同步加载当前块，重叠从第二轮才开始
B. 编译器会跳过第一轮
C. 第一轮必须用标量加载
D. 第一轮数据不重要
【正确答案】A
【详细解析】

2. **选项分析**：A 正确；B、C、D 错。
3. **业务延伸**：这解释了为什么短 K 循环的 kernel 用流水线收益不明显（填充期占比高），而长循环收益显著。也提示：对 K/V 长度很短的场景，应选择更简单的实现而不是强行流水线。

A. 必须关闭所有同步
B. 只要硬件支持就一定有效
C. 相邻 kernel 之间存在可重叠的"启动阶段"（如索引计算、参数读取、初始化），且后一个 kernel 有一段"不依赖上游数据"的前置工作可提前执行；若后一个 kernel 一开始就读上游输出，重叠空间几乎为零

【选项】
A. 自动使用共享内存

A. block 越大，跨 warp 归约需要经过共享内存的层级越多、同步成本越高，且单个 block 占用的资源更多、可驻留 block 数更少；block=256 在多数归约场景是更常见的折中

### 第 161 题
【题型：单选题】【难度：高阶】
【题干】某模型 head dim = 128、GQA ratio = 8。工程师想把 attention 的 query tile 宽度设为 16 以最大化 K/V 复用，但实测不如宽度 8。最合理的定量解释是？
【选项】
A. 宽度超过 8 会触发数值错误
B. 宽度从 8 提到 16 时，K/V 复用次数并未增加（因为一个 K/V head 只对应 8 个 Q head），但输出累加器与分数缓冲的片上占用翻倍，导致 occupancy 下降、延迟隐藏能力减弱
C. 宽度必须是 ratio 的倍数，16 不是 8 的倍数
D. K/V 复用次数随宽度线性增长，16 一定优于 8
【正确答案】B
【详细解析】
1. **核心原理**：tile 宽度带来的 K/V 复用上限是 GQA ratio——一个 K/V head 最多被 ratio 个 Q head 共享。当宽度超过 ratio 后，新增的宽度只是"多塞了几组 Q head"，每组需要各自的 K/V（或复用不同 K/V），复用收益不再增长，而 o 累加器（宽度 × head dim）与分数缓冲（宽度 × KV tile）的占用线性增长。设宽度 W、head dim d，o 累加器约占 W·d 个寄存器，W 从 8 到 16 直接翻倍。
2. **选项分析**：A 错；B 正确；C 错，不存在"必须是 ratio 倍数"的硬约束（宽度是 block 的 query 数，可跨 head 分组）；D 错，复用次数在 W > ratio 后不再增长。
3. **业务延伸**：选宽度的定量方法是：先算"复用收益 = min(W, ratio)"，再算"资源代价 ∝ W·(d + KV_tile)"，找收益/代价的最优点。这也解释了为什么 ratio=1 时宽 tile 几乎总是亏——收益恒为 1，代价线性增长。

【选项】
A. 直接把各段输出相加
B. 按 online softmax 的三元组合并：取各段最大值的最大值作为新基准，用各自的 l 与 m 做重标定后再合并 o 与 l，最后统一除以合并后的 l

1. **核心原理**：稀疏路径的总时间 = 索引构建 + 稀疏 kernel。稀疏 kernel 时间 ≈ 稠密时间 × 可见比例 ÷ gather 效率（< 1 的效率损失来自非连续访存）。只有"索引构建 + 稀疏" < "稠密"才值得。
2. **选项分析**：A、B、C 都是把"长度/比例"当充分条件的错误判据；D 正确。
3. **业务延伸**：实测方法是三组对照（可见 100% / 25% / 5%），分别记录索引构建时间、稀疏 kernel 时间、稠密 kernel 时间。只有当可见比例足够低（通常 < 25%）且结构块状时才明显划算。
