# 模块四 · GGML-CUDA 性能调优（原理业务版 · 150 题）

> 定位：全部题目以**真实业务场景**为出发点（在线低延迟服务、离线批量推理、OOM、吞吐上不去、首 token 慢、长上下文变慢、多卡负载不均、并发上不去等），考察「**现象 → 瓶颈 → 手段 → 代价**」的工程判断力。
> 禁止项：不考「参数在哪个文件」「环境变量怎么拼写」「源码第几行」这类纯定位/记忆题；可提及编译选项、环境变量、kernel 名，但提问角度必须是**业务效果、场景取舍、代价与定位方法**。
> 配比：总 150 题 = **单选 90 / 多选 60**；难度 **基础 45 / 进阶 75 / 高阶 30**。
> 分部分：第一部分·基础（第 1–45 题）→ 第二部分·进阶（第 46–120 题）→ 第三部分·高阶（第 121–150 题）。
> 每题固定五段：题型/难度 → 题干 → 选项 → 正确答案 → 详细解析（核心原理 / 选项分析 / 业务延伸）。

---

## 第一部分 · 基础题（第 1–45 题）

### 第 1 题
【题型：单选题】【难度：基础】
【题干】某在线对话服务，单条请求的 decode（逐 token 生成）阶段，每步只生成 1 个 token。该阶段最主要的瓶颈通常是？
【选项】
A. 算力受限，因为矩阵乘的规模很大
B. 访存受限，因为每生成 1 个 token 都要把几乎全部权重从显存读一遍
C. 网络带宽受限
D. 编译选项受限
【正确答案】B
【详细解析】
1. **核心原理**：decode 每步 batch 很小（在线服务常为 1），计算量约等于「权重字节数 × 2 次浮点运算/参数」，而从显存读取的数据量约等于全部权重。算术强度只有 1~2 FLOP/Byte，远低于 GPU 的算力/带宽比（roofline 拐点，消费级卡常在几十甚至上百），因此落在「访存受限」区。
2. **选项分析**：A 把「矩阵乘」等同于「算力密集」是常见误区——矩阵乘在小 batch 退化成矩阵-向量乘（GEMV），运算量太小喂不饱 SM；C 与 D 与单机 decode 瓶颈无关。
3. **业务延伸**：既然瓶颈是「把权重读一遍」，提速方向就锁定三条：①降低权重字节数（量化）；②提高每次读取的复用（增大 batch 摊薄）；③提高读取效率（带宽、缓存）。任何「优化计算指令数」的思路在 decode 上收效都有限。

### 第 2 题
【题型：单选题】【难度：基础】
【题干】同一次推理，把 8K token 的长 prompt 一次性喂进去做 prefill 阶段，其性能特征通常是？
【选项】
A. 访存受限，与 decode 完全一样
B. 算力受限：矩阵乘的运算量随 token 数线性增长，算术强度高，能喂饱 SM
C. 与 prompt 长度无关
D. 只受显存容量限制
【正确答案】B
【详细解析】
1. **核心原理**：prefill 把整个 prompt 当作 batch 维做矩阵乘，规模是「(prompt_len) × hidden × hidden」量级，权重被复用 prompt_len 次，算术强度高，进入算力受限区。
2. **选项分析**：A 混淆了 prefill 与 decode；C 忽略了 prefill 的二次方注意力项；D 把「容量」当「瓶颈」。
3. **业务延伸**：这就是「同一次请求里，prefill 慢是算力问题、decode 慢是带宽问题」的根因。调优时 prefill 关注 GEMM 效率（大 tile、cuBLAS/MMQ），decode 关注访存与启动开销。首 token 延迟（TTFT）主要由 prefill 决定。

### 第 3 题
【题型：多选题】【难度：基础】
【题干】以下哪些现象提示当前推理很可能处于「访存受限」？（多选）
【选项】
A. 增大 batch 后吞吐明显上升，而单步延迟增幅不大
B. GPU 的 SM 计算单元利用率很低（如 <20%），但显存带宽占用接近峰值
C. 把权重从 FP16 换成 4bit 后，decode 速度明显变快
D. 把 GPU 换成算力翻倍、带宽相同的卡，decode 速度几乎不变
【正确答案】ABCD
【详细解析】
1. **核心原理**：访存受限的本质是「数据搬运跟不上计算」。其可观测特征包括：加 batch 有效（复用读取）、算力单元闲置而带宽吃满、减少数据量（量化）有效、换更高算力但同带宽的卡无效。
2. **选项分析**：A、B、C、D 全部指向「瓶颈在带宽侧」。若换带宽翻倍、算力相同的卡速度明显变快，同样佐证访存受限。
3. **业务延伸**：判断瓶颈最快的「敏感度实验」：分别改变带宽相关因素（量化等级、batch）与算力相关因素（换卡、换更快的 GEMM 实现），看哪个对端到端更敏感。这一步做对了，后面所有优化才不跑偏。

### 第 4 题
【题型：单选题】【难度：基础】
【题干】「算术强度（arithmetic intensity）」这个指标衡量的是？
【选项】
A. 显存带宽的峰值
B. 每从显存搬运 1 字节所对应的浮点运算次数
C. kernel 的线程占用率
D. 显存容量与算力之比
【正确答案】B
【详细解析】
1. **核心原理**：算术强度 = 总浮点运算数 / 总访存字节数，单位 FLOP/Byte。把它与硬件的「算力/带宽比」比较：低于该比值 → 访存受限；高于 → 算力受限。roofline 模型正是用这条分界线判断上限。
2. **选项分析**：A、C、D 分别描述带宽、占用率、容量算力比，都不是算术强度的定义。
3. **业务延伸**：估算是调优的基本功。比如一个 GEMV（batch=1）的算术强度≈2/（权重字节/参数），一眼就能判定它必然访存受限；而大 GEMM 的算术强度≈2N（N 为 batch），一眼就能判定它算力受限。先算再调，避免南辕北辙。

### 第 5 题
【题型：单选题】【难度：基础】
【题干】面向在线交互式对话服务（用户盯着屏幕逐字看），最影响体验、应优先保障的指标是？
【选项】
A. 峰值吞吐（token/s）
B. 首 token 延迟（TTFT）与后续单 token 间隔
C. 显存占用绝对值
D. 编译时间
【正确答案】B
【详细解析】
1. **核心原理**：交互式场景下用户感知的是「多久开始出字」和「出字有多快」，即 TTFT 与 inter-token latency。吞吐再高，如果第一个字等 5 秒，体验依然崩坏。
2. **选项分析**：A 是离线批量的首要指标；C、D 是约束条件或开发效率，不是用户体验指标。
3. **业务延伸**：这决定了在线服务与离线批量的优化方向完全不同——在线优先压 TTFT 与单步延迟（小 batch、快速 prefill），离线优先压总吞吐（大 batch、连续批处理）。选错目标，优化越多越偏。

### 第 6 题
【题型：多选题】【难度：基础】
【题干】关于增大 batch（一次同时处理的请求数），下列说法正确的是？（多选）
【选项】
A. 吞吐通常上升（权重读取被更多 token 复用）
B. 单步延迟通常上升
C. 显存占用（尤其 KV cache 与激活）通常上升
D. 吞吐和延迟都能无限改善
【正确答案】ABC
【详细解析】
1. **核心原理**：batch 增大让同一份权重服务更多 token，算术强度上升、带宽利用率提高，吞吐上升；但每步要算的 token 变多，单步延迟上升；同时每个请求都要独立 KV cache，显存线性上升。
2. **选项分析**：D 是典型的「免费午餐」误区——吞吐与延迟存在权衡，且受显存上限约束，不能无限改善。
3. **业务延伸**：实际工程是「在显存与延迟 SLA 约束下找最优 batch」。在线服务宁可牺牲吞吐也要压延迟，离线服务则把 batch 拉到显存允许的最大值。这条权衡是后面所有 batch 类题目的总纲。

### 第 7 题
【题型：单选题】【难度：基础】
【题干】KV cache 的显存占用，随下列哪组量近似线性增长？
【选项】
A. batch 大小与上下文长度
B. 权重量化等级
C. GPU 核心频率
D. 编译架构
【正确答案】A
【详细解析】
1. **核心原理**：KV cache 大小 ≈ 2（K 和 V）× 层数 × head 数 × head_dim × 序列长度 × batch × 数据类型字节数。在模型固定的前提下，它与「序列长度 × batch」成正比。
2. **选项分析**：B 影响的是权重显存与访存量；C、D 与显存占用无关。
3. **业务延伸**：这就是「长上下文 / 高并发吃显存」的根本原因。做容量规划时，先用该公式估一遍：若上下文翻 4 倍、并发翻 2 倍，KV 就涨 8 倍，往往比权重还大，是 OOM 的首要嫌疑。

### 第 8 题
【题型：单选题】【难度：基础】
【题干】推理服务在压力测试时突发 OOM，排查的合理第一步是？
【选项】
A. 立刻换一张更大显存的卡
B. 先量出各部分显存占用（权重 / KV cache / 临时 workspace / 碎片），定位是哪一块涨上去的
C. 直接把 batch 降到 1 了事
D. 重装显卡驱动
【正确答案】B
【详细解析】
1. **核心原理**：显存由多块构成，OOM 只是「总和超限」的表象。只有先分解出权重、KV、临时缓冲、碎片各占多少，才能对症下药。
2. **选项分析**：A 是「用钱掩盖问题」，成本高且掩盖真实原因；C 牺牲了本可保留的性能；D 与显存占用无关。
3. **业务延伸**：定位顺序建议：①模型权重（固定，最先估）→ ②KV cache（随并发×长度增长，最易失控）→ ③临时 workspace（看是否有异常增长或泄漏）→ ④碎片（长时间运行后碎片累积）。多数「跑一会儿才 OOM」属于 KV 或碎片问题。

### 第 9 题
【题型：多选题】【难度：基础】
【题干】推理显存不足时，下列哪些是可行的缓解手段？（多选）
【选项】
A. 降低上下文长度上限，或限制 KV cache 总量
B. 提高权重量化等级（用更低位宽）
C. 限制并发请求数
D. 把权重全部保留为 FP16 以「减少转换开销」
【正确答案】ABC
【详细解析】
1. **核心原理**：省显存的三条主线：①砍 KV（限长度、限并发）；②砍权重（量化）；③复用/回收（池化、分页）。A、B、C 分别命中前两条。
2. **选项分析**：D 反其道而行——FP16 权重比量化权重更占显存，属于加重问题而非缓解。
3. **业务延伸**：这些手段都有代价：限长度损害长文档场景，限并发损害吞吐，量化可能损失精度。工程上应按「精度损失最小、业务影响最小」排序，通常先限并发、再上 KV 量化、最后才动权重精度。

### 第 10 题
【题型：单选题】【难度：基础】
【题干】一般情况下，把权重量化从 FP16 降到 4bit，主要收益是？
【选项】
A. 显存占用显著下降，同时 decode 阶段访存量下降、速度提升
B. 精度一定提升
C. 首 token 延迟一定下降
D. 算力一定翻倍
【正确答案】A
【详细解析】
1. **核心原理**：权重从 2 字节降到约 0.5 字节，显存与每步需读取的字节数同步下降。decode 访存受限，所以速度随字节数下降而提升。
2. **选项分析**：B 恰恰相反（量化有精度损失）；C 首 token 由 prefill 主导，量化对 prefill 未必有正收益（还要反量化）；D 算力不因量化改变。
3. **业务延伸**：量化是 decode 提速最有效的手段之一，但要注意：它优化的是「访存」，对「算力受限」的 prefill 帮助有限，甚至因反量化开销略变慢。这就是为什么同一模型 prefill 与 decode 的量化收益不同。

### 第 11 题
【题型：单选题】【难度：基础】
【题干】基准测试里报告的 token/s（如生成 128 token 的速度），通常指的是？
【选项】
A. 首 token 延迟
B. 稳定解码阶段平均每秒钟生成的 token 数
C. 显存带宽
D. 单算子耗时
【正确答案】B
【详细解析】
1. **核心原理**：生成速度指标区分两段：prefill（决定 TTFT）与 decode（决定 token/s）。ttg/tg 类指标统计的是 decode 阶段稳态速度，通常已排除首 token。
2. **选项分析**：A 是另一个独立指标；C、D 是底层量，不是端到端速度。
3. **业务延伸**：看报告时要区分「生成速度」与「处理速度」（prompt token/s）。只报一个数字极易误导：一个模型可能 prompt 处理很快（prefill 强）但生成很慢（decode 弱），反之亦然。选型时必须两个都看。

### 第 12 题
【题型：多选题】【难度：基础】
【题干】基准测试必须先「预热（warmup）」再计时，主要原因有？（多选）
【选项】
A. 首次 kernel 需要模块加载、上下文初始化，耗时异常高
B. 首次运行会触发显存池生长、CUDA Graph 首次录制等一次性开销
C. GPU 频率/功耗状态需要爬升到稳态
D. 预热会让模型数值精度变高
【正确答案】ABC
【详细解析】
1. **核心原理**：冷启动包含大量一次性开销：CUDA 上下文建立、kernel 模块加载、显存池首次分配、图捕获首录、GPU 从低频爬升到稳态频率。这些若不排除，会把测量值拉低。
2. **选项分析**：D 是错的——预热不改变数值精度，只影响时序。
3. **业务延伸**：不预热是性能测量最常见的坑之一：可能测出「慢 30%」的假象，让人去优化根本不存在的瓶颈。规范做法是丢弃前若干次迭代、取稳态均值，并报告方差。

### 第 13 题
【题型：单选题】【难度：基础】
【题干】编译时指定的目标 GPU 架构（compute capability）与实际运行的卡不匹配，最可能的后果是？
【选项】
A. 程序无法编译
B. 运行时报找不到对应 kernel 镜像，或退回兼容/较慢路径，性能明显下降
C. 显存容量翻倍
D. 数值精度必然出错
【正确答案】B
【详细解析】
1. **核心原理**：CUDA 代码按架构编译成 PTX/SASS。若目标架构不含实际卡的 SASS，则需 JIT 编译 PTX（首次慢）或直接找不到镜像报错；若只编了较低架构，则会走不到该卡的新指令（如更新的矩阵指令），性能受限。
2. **选项分析**：A 通常不成立（编译能过）；C、D 与架构无关。
3. **业务延伸**：这是「同二进制换机器性能差异巨大」的经典根因。部署前应确认编译架构覆盖目标卡，尤其是新旧卡混布的集群，务必为每档架构都编一份或至少包含可 JIT 的 PTX。

### 第 14 题
【题型：单选题】【难度：基础】
【题干】「多卡一定比单卡快」，这个说法？
【选项】
A. 正确
B. 错误：跨卡通信开销、负载不均、切分比例不当都可能让多卡反而更慢
C. 只在 NVLink 下正确
D. 只在 PCIe 下正确
【正确答案】B
【详细解析】
1. **核心原理**：多卡引入两类新成本：①跨卡通信（每层都要同步）；②同步等待与负载不均。若单卡算力已足够、或模型小到通信占比过高，多卡可能因通信开销而更慢。
2. **选项分析**：A 是典型误区；C、D 把结论简化为互联类型，忽略了「是否值得切分」这个前提。
3. **业务延伸**：决定多卡是否划算的判据：单卡装不下（显存不够）时几乎必用多卡；单卡装得下时，只有「算力明显不足且通信开销可控」才值得切分。切分前先估通信量占端到端的比例。

### 第 15 题
【题型：多选题】【难度：基础】
【题干】NVLink 相比 PCIe，对多卡推理的业务影响包括？（多选）
【选项】
A. 跨卡带宽更高，张量并行、通信密集场景收益更大
B. 通信开销占端到端比例更小，同步等待更短
C. 能直接提升单卡的算力
D. 让通信更不易成为瓶颈，从而缓解负载不均带来的后果
【正确答案】ABD
【详细解析】
1. **核心原理**：NVLink 提供远高于 PCIe 的卡间带宽与更低的延迟，直接影响「跨卡通信」这一多卡推理的主要附加成本。
2. **选项分析**：C 错误——互联只影响卡间数据传输，不改变单卡 FLOPS。
3. **业务延伸**：这解释了为什么同一套多卡方案在不同机器上表现迥异：PCIe 集群上张量并行的通信开销可能吃掉大部分收益，NVLink 集群则能保留。部署选型时，互联拓扑是与卡数同等重要的变量。

### 第 16 题
【题型：单选题】【难度：基础】
【题干】首 token 延迟（TTFT）通常由什么主导？
【选项】
A. 解码阶段逐步生成
B. prefill 阶段处理整个 prompt 的时间（外加排队）
C. 显存回收
D. 编译时间
【正确答案】B
【详细解析】
1. **核心原理**：用户发出请求后，服务必须先读完整个 prompt（prefill）才能吐出第一个 token，因此 TTFT ≈ 排队时间 + prefill 时间。
2. **选项分析**：A 对应的是后续 token 间隔；C、D 不是主因。
3. **业务延伸**：优化 TTFT 的抓手：①减少排队（调度、并发控制）；②加速 prefill（更高效的 GEMM、合理 batch、KV cache 复用/前缀共享）。长 prompt 场景下，prefill 时间往往与 prompt 长度近似线性，需要专门设计。

### 第 17 题
【题型：单选题】【难度：基础】
【题干】连续批处理（continuous batching）的核心意义是？
【选项】
A. 让所有请求必须同时开始
B. 请求一旦结束就腾出槽位、新请求立即补入，避免等整批做完，从而提高 GPU 利用率与吞吐
C. 把单请求延迟降到 0
D. 减少模型参数量
【正确答案】B
【详细解析】
1. **核心原理**：静态批处理要等整批所有请求都生成完才进入下一批，短请求会拖累/被拖累，GPU 出现空转。连续批处理在每次 decode 步都重新组批，完成即退出、等待即补入。
2. **选项分析**：A 是静态批的特征；C、D 与批处理机制无关。
3. **业务延伸**：连续批处理是在线服务吞吐的关键机制，尤其当请求长度差异大时收益显著。代价是调度与 KV 管理更复杂（需要动态分配/回收 KV 槽位），这也是「分页 KV」等机制出现的原因。

### 第 18 题
【题型：多选题】【难度：基础】
【题干】CUDA 异步执行给「性能计时」带来的坑包括？（多选）
【选项】
A. CPU 侧计时会在 kernel 真正完成前就返回，导致测得过快
B. 不显式同步就读结果会拿到未完成的数据
C. 首次报出的错误可能滞后到后续调用才暴露，误导定位
D. 异步会让 GPU 根本不执行 kernel
【正确答案】ABC
【详细解析】
1. **核心原理**：CUDA kernel 默认异步：启动调用立即返回，GPU 在后台排队执行。若不 cudaDeviceSynchronize / 事件同步就计时，测到的是「启动耗时」而非「执行耗时」。
2. **选项分析**：D 错误——异步不代表不执行，只是 CPU 不等它。
3. **业务延伸**：正确计时要么用 CUDA event 夹住目标区间，要么在计时前后强制同步。异步还会让错误「漂移」：一个越界 kernel 可能在几步之后才报 illegal memory access，定位时要以「最早出现异常的调用」为线索回溯。

### 第 19 题
【题型：单选题】【难度：基础】
【题干】你优化了某个 kernel，单算子耗时明显下降，但端到端吞吐几乎没变。最可能的原因是？
【选项】
A. 该算子本来就不是端到端瓶颈
B. 测量工具坏了
C. GPU 出现故障
D. 显存不够
【正确答案】A
【详细解析】
1. **核心原理**：端到端耗时由瓶颈算子决定。优化一个占比很小的算子，即使它快了一倍，对总时间的影响也微乎其微（Amdahl 定律）。
2. **选项分析**：B、C、D 是回避性解释，未触及「瓶颈占比」这一核心。
3. **业务延伸**：正确姿势是先做耗时分解，找出占比最高的 top-N 算子，把优化火力集中在那里。盲目优化「看起来慢」的算子，是性能工作最常见的浪费。

### 第 20 题
【题型：单选题】【难度：基础】
【题干】把模型的更多层驻留到 GPU（而非放 CPU）对性能的意义是？
【选项】
A. 避免每步在 CPU 与 GPU 间搬运权重，从而大幅提升 decode 速度
B. 提升数值精度
C. 减少显存占用
D. 提高首 token 延迟
【正确答案】A
【详细解析】
1. **核心原理**：若权重在 CPU，decode 每步都要经 PCIe 把该层权重传到 GPU，PCIe 带宽远低于显存带宽，会成为严重瓶颈。驻留 GPU 后权重读取走显存，速度大幅提升。
2. **选项分析**：B 与精度无关；C 相反（驻留更占显存）；D 驻留是降低而非提高延迟。
3. **业务延伸**：这是「显存不够时部分层放 CPU」方案的代价来源：每多放一层在 CPU，就多一次跨 PCIe 搬运。所以要么全驻留（显存够），要么在「显存不足」与「PCIe 拖慢」之间权衡层数，通常优先把计算密集、访存大的层留 GPU。

### 第 21 题
【题型：多选题】【难度：基础】
【题干】关于性能调优方法论，下列正确的是？（多选）
【选项】
A. 先定位瓶颈（算力/访存/通信/启动开销），再针对性优化
B. 每次只改一个变量做对照实验
C. 改动后同时验证正确性与性能
D. 凭直觉一次改多处，节省时间
【正确答案】ABC
【详细解析】
1. **核心原理**：性能优化的科学方法是「测量 → 假设 → 单变量实验 → 验证」。先定位瓶颈避免瞎优化，单变量保证因果清晰，正确性+性能双验证防止「跑得快但算错了」。
2. **选项分析**：D 恰恰破坏了因果可归因性——一次改多处，快了慢了都不知道是谁的功劳/锅。
3. **业务延伸**：这套方法论在 kernel 调优里尤其重要，因为 GPU 行为复杂、直觉常失效。建立「基线 → 改动 → 回归」的固定流程，比任何单点技巧都更值钱。

### 第 22 题

【题干】优化 kernel 后，除了性能提升，还必须验证什么？
【选项】
A. 数值正确性：与参考实现（CPU/高精度路径）对齐，误差在容差内

2. **选项分析**：B、C、D 是代码质量指标，不是优化验收的必要条件。

### 第 23 题
【题型：单选题】【难度：基础】
【题干】吞吐（throughput）与延迟（latency）之间的关系通常是？
【选项】
A. 完全独立，互不影响
B. 存在权衡：通过增大 batch 提高吞吐，往往以牺牲单请求延迟为代价
C. 总是同向提升
D. 吞吐越高延迟一定越低
【正确答案】B
【详细解析】
1. **核心原理**：增大 batch 让 GPU 更饱和（吞吐↑），但每个请求要等的「步」更长、排队更久（延迟↑）。二者常呈此消彼长的帕累托关系。
2. **选项分析**：A、C、D 都忽视了排队与批处理带来的耦合。
3. **业务延伸**：工程上要在「延迟 SLA」与「吞吐成本」之间找平衡点，画出延迟-吞吐曲线，选满足 SLA 的最优点。在线服务偏向低延迟侧，离线批量偏向高吞吐侧，这正是两类系统架构不同的根源。

### 第 24 题
【题型：单选题】【难度：基础】
【题干】把服务的上下文长度上限从 2K 提升到 32K，显存方面最直接的变化是？
【选项】
A. KV cache 占用大幅上升，可能直接 OOM
B. 模型权重占用上升
C. 显存占用完全不变
D. 显存带宽下降
【正确答案】A
【详细解析】
1. **核心原理**：KV cache 与序列长度成正比。上限从 2K 到 32K 是 16 倍，若按最坏情况预分配或实际长请求增多，KV 显存会显著膨胀。

### 第 25 题

A. 模型本来就能装进单卡，且单卡算力已足够
B. 卡间只有 PCIe 且通信密集，通信开销吃掉收益

### 第 29 题

【题干】显存带宽（memory bandwidth）对推理性能的意义是？

A. 决定访存受限算子（如 decode 的 GEMV、Attention 读 KV）的速度上限
B. 决定显存容量

### 第 30 题
【题型：单选题】【难度：基础】
【题干】启用 CUDA Graph（图捕获）最能带来收益的场景是？
【选项】
A. 小 batch、短序列、kernel 启动开销在总耗时中占比高的 decode
B. 超大 batch 的 prefill
C. 模型训练
D. 模型加载阶段

### 第 33 题
【题型：单选题】【难度：基础】
【题干】长上下文推理（如 32K）明显变慢，主要开销通常来自？
【选项】
A. 权重量化
B. 注意力计算与 KV 读取随上下文长度增长
C. 编译时间
D. 显存池
【正确答案】B
【详细解析】
1. **核心原理**：随上下文增长，注意力部分的计算量与 KV 读取量都随之上升（注意力分数矩阵规模随长度二次增长，KV 读取随长度线性增长），逐渐成为主要开销；权重相关开销则与长度无关。
2. **选项分析**：A、C、D 与「随长度变慢」这一现象不匹配。
3. **业务延伸**：这就是长上下文需要专门优化注意力（分块在线 softmax、减少 KV 读取、KV 量化/分片）的原因。短上下文时注意力占比小、可忽略；一旦超过某个长度阈值，它就成了瓶颈，优化重点随之迁移。

### 第 34 题
【题型：多选题】【难度：基础】
【题干】影响 decode 速度（token/s）的因素有？（多选）
【选项】
A. 权重的字节数（量化等级）
B. 显存带宽
C. batch 大小
D. 模型文件名的长度
【正确答案】ABC
【详细解析】
1. **核心原理**：decode 访存受限，速度 ≈ 带宽 / 每步需读取的字节数。权重字节数（A）、带宽（B）直接决定上限；batch（C）通过复用读取影响有效速度。
2. **选项分析**：D 是明显的干扰项，与性能无关。
3. **业务延伸**：据此可建立 decode 速度的粗略估算式，用于快速判断某模型在某卡上「理论能到多少 token/s」，从而识别实际值是接近上限（已优化好）还是差距很大（还有空间）。

### 第 35 题
【题型：单选题】【难度：基础】
【题干】多卡推理时出现「某一张卡利用率高、其余卡很闲」，最可能的原因是？
【选项】
A. 负载/切分不均衡，或其余卡在等通信
B. 完全正常的现象
C. 显存不足
D. 数值精度问题
【正确答案】A
【详细解析】
1. **核心原理**：多卡并行要求各卡工作量均衡并同步推进。若切分比例不均，或某卡承担的通信/特殊算子更重，就会形成「木桶效应」——整体被最忙的卡拖住，其余卡空等。
2. **选项分析**：B 把异常当正常；C、D 与利用率不均无直接关系。
3. **业务延伸**：排查时逐卡看利用率和显存，找出「最忙的那张」在干什么（是计算重还是通信重）。均衡切分、把通信与计算重叠、必要时调整层/头分配，都是常见手段。

### 第 36 题
【题型：单选题】【难度：基础】
【题干】多卡张量切分比例设置不当，最直接的后果是？
【选项】
A. 各卡工作量差异大，快卡等慢卡，整体被最慢的卡拖住
B. 数值精度自动提升
C. 显存容量翻倍
D. 程序无法启动
【正确答案】A
【详细解析】
1. **核心原理**：张量并行把每层的计算切到各卡，各卡必须等齐才进入下一步。若某卡分到的计算量更大（如注意力头数无法均分、某个特殊层未切分），它就成了关键路径。
2. **选项分析**：B、C 与切分比例无关；D 通常不成立（切分不均一般不导致启动失败）。
3. **业务延伸**：切分时尽量让各卡计算量相等，尤其注意不能整除的维度（如 head 数、专家数）。对无法均分的部分，可用「多分一点给空闲卡」的策略，或改用更易均衡的并行方式（如流水线并行）。

### 第 37 题
【题型：多选题】【难度：基础】
【题干】推理框架中「显存复用」机制的常见形式包括？（多选）
【选项】
A. 显存池化，避免频繁分配/释放
B. 计算图中生命周期不重叠的缓冲复用同一块显存
C. KV cache 分页/分块管理，按需分配回收
D. 每个算子都重新 cudaMalloc 一块新缓冲
【正确答案】ABC
【详细解析】
1. **核心原理**：显存复用有三层：①分配器层面池化；②图层面按张量生命周期复用地址；③KV 层面分页管理，动态分配回收。目的都是「在有限显存里装下更多工作」。
2. **选项分析**：D 是反模式——频繁分配释放既慢又易碎片化。
3. **业务延伸**：显存复用是「为什么峰值显存不等于所有张量之和」的原因，也是支持更大 batch/更长上下文的基础。排查「显存比预期高」时，要确认复用机制是否生效（是否有不该长期驻留的缓冲）。

### 第 38 题
【题型：单选题】【难度：基础】
【题干】为什么大模型 decode 阶段主要瓶颈是显存带宽而非算力？
【选项】
A. 因为每生成 1 个 token 都要把几乎全部权重从显存读一遍，而计算量相对很小
B. 因为 GPU 算力太弱
C. 因为显存容量太小
D. 因为 kernel 一定写错了
【正确答案】A
【详细解析】
1. **核心原理**：batch=1 时，权重读一次只用一次（每个权重参与的计算极少），数据搬运量远超计算量，算术强度极低，因而受带宽而非算力限制。
2. **选项分析**：B、C、D 都是错误归因；瓶颈是「数据量与计算量的比例」问题，不是设备绝对性能问题。
3. **业务延伸**：这解释了「为什么大模型在强算力卡上 decode 依然不快」——算力再高，也要先把权重搬进来。破解之道：量化减数据、增大 batch 增复用、或减少每步读取量（如稀疏/MoE 只读激活专家）。

### 第 39 题
【题型：单选题】【难度：基础】
【题干】服务出现「首 token 很慢但后续很快」与「首 token 很快但后续很慢」，二者的根因通常分别是？
【选项】
A. 前者多为 prefill/排队问题，后者多为解码阶段访存或 batch 过大问题
B. 两者都是显存问题
C. 两者都是网络问题
D. 无法区分，只能靠猜
【正确答案】A
【详细解析】
1. **核心原理**：TTFT 由 prefill+排队决定，后续速度由 decode 决定。两个指标分别慢，指向不同的优化对象。
2. **选项分析**：B、C 把两类症状笼统归因；D 否定了可分解性——实际上通过分段测量完全可以区分。
3. **业务延伸**：分段测量是定位的第一步：分别测 prefill 时间与 decode 速度。首 token 慢就查 prompt 处理与调度；后续慢就查权重访存、batch 配置、Attention 开销。

### 第 40 题
【题型：单选题】【难度：基础】
【题干】KV cache 分片（把不同层/头的 KV 放到不同卡）的主要意义是？
【选项】
A. 把 KV 显存压力分摊到多卡，从而支持更长上下文或更大并发
B. 提升数值精度
C. 减少模型权重的显存占用
D. 加快编译
【正确答案】A
【详细解析】
1. **核心原理**：KV cache 在长上下文/高并发时可能是显存大户，单卡放不下。分片让每张卡只存一部分 KV，突破单卡容量限制。
2. **选项分析**：B、D 与分片无关；C 分片的是 KV，不是权重。
3. **业务延伸**：KV 分片常与「按头/按层并行」配合，代价是注意力计算需要跨卡通信（各卡算完部分注意力后要合并）。因此它适合「KV 是显存瓶颈且通信可接受」的场景，通信太慢时收益有限。

### 第 41 题
【题型：多选题】【难度：基础】
【题干】关于量化与 KV cache 策略的组合取舍，正确的是？（多选）
【选项】
A. 对 KV cache 也做量化能显著降低长上下文显存，但可能影响精度
B. 权重低比特量化主要省权重显存、加快 decode 访存
C. 量化等级越低，结果一定越准
D. 权重与 KV 量化是两件独立的事，需分别权衡
【正确答案】ABD
【详细解析】
1. **核心原理**：权重与 KV 是两处独立的显存与访存来源。权重压缩主要提速 decode、省权重显存；KV 压缩主要省长上下文显存、支持更大并发/长度。两者各有精度代价。
2. **选项分析**：C 错误——量化等级越低（位宽越小）通常精度损失越大，不存在「越低越准」。
3. **业务延伸**：组合策略要分场景：短上下文可只压权重；长上下文必须同时压 KV，否则 KV 会盖过权重成为显存瓶颈。压缩前务必用质量评测（困惑度、任务指标）确认精度可接受，再上生产。

### 第 42 题
【题型：单选题】【难度：基础】
【题干】在线服务「并发上不去、QPS 上不去」，下列哪项通常不是根因？
【选项】
A. 单请求占用显存（尤其 KV）过多，限制了并发槽位
B. 单步延迟高，导致单卡吞吐受限
C. 批处理策略不当（如必须等满批才执行）
D. 模型权重的文件名太长
【正确答案】D
【详细解析】
1. **核心原理**：并发/QPS 受限于「显存能容纳的并发槽位」与「单步延迟」。显存占用大 → 槽位少；单步慢 → 单位时间吞吐低；批处理策略差 → GPU 空转。
2. **选项分析**：A、B、C 都是真实根因；D 与性能无关，是干扰项。
3. **业务延伸**：提升并发的抓手：①压 KV（量化/分页/分片）腾槽位；②降单步延迟（量化、图捕获、减少同步）；③改进调度（连续批处理、动态组批）。先量出「瓶颈在槽位还是延迟」，再对症。

A. 用 profiler 看各 kernel 的耗时占比
B. 观察 GPU 利用率与显存带宽占用

### 第 45 题

A. 只看平均耗时，忽略首 token 与长尾延迟

### 第 46 题
【题型：单选题】【难度：进阶】
【题干】某卡算力约 60 TFLOP/s、显存带宽约 1.5 TB/s，则其 roofline 拐点（算力/带宽比）约为 40 FLOP/Byte。某算子的算术强度估算为 3 FLOP/Byte，结论是？
【选项】
A. 该算子算力受限，应优化计算指令
B. 该算子访存受限，应减少访存或提高数据复用
C. 无法判断
D. 该算子已到性能上限，无需优化
【正确答案】B
【详细解析】
1. **核心原理**：roofline 判据：算术强度 < 拐点（40）→ 访存受限；> 拐点 → 算力受限。3 远小于 40，明确访存受限。
2. **选项分析**：A 方向错了；C 忽视了可估算性；D 把「受限」误当「到顶」——访存受限仍有优化空间（减数据量、增复用）。
3. **业务延伸**：工程上先用这套估算给每个热点算子归类，再决定优化策略：访存受限 → 量化/融合/提高复用；算力受限 → 更好的分块、张量核、减少冗余计算。归类错了，优化白费。

### 第 47 题
【题型：多选题】【难度：进阶】
【题干】用「敏感度实验」判断瓶颈在带宽还是算力，下列哪些做法合理？（多选）
【选项】
A. 固定模型，改变权重量化等级，看速度是否明显变化
B. 固定一切，增大 batch，看吞吐是否明显上升
C. 把同一份代码放到「算力翻倍、带宽不变」的卡上跑，看是否变快
D. 只看代码里 for 循环的层数，推断瓶颈
【正确答案】ABC
【详细解析】
1. **核心原理**：判瓶颈的本质是「改哪个自变量，因变量敏感」。改带宽相关量（量化、batch）敏感 → 访存受限；改算力相关量（换卡）敏感 → 算力受限。
2. **选项分析**：A、B、C 都是可控的单变量敏感度实验；D 是静态代码推测，与运行时瓶颈无必然关系。
3. **业务延伸**：这三个实验互补：A、B 在同一台机器上就能做，C 需要另一张卡但最直接。三者结论一致时，判断最可靠。实验前务必固定其他变量（同模型、同序列长度、同并发）。

### 第 48 题
【题型：单选题】【难度：进阶】
【题干】一个 bat 的 GEMV：权重矩阵 M×N、数据 4bit。忽略其他开销，其算术强度大约是？
【选项】
A. 约等于 4（每个权重约 2 FLOP，每权重约 0.5 字节，只读一次）
B. 约等于 N（随 N 线性增长）
C. 约等于 M×N
D. 恒为 1
【正确答案】A
【详细解析】
1. **核心原理**：bat 时每个权重参与约 2 次浮点运算（一次乘、一次加），而它只被读取一次。故 FLOP/Byte ≈ 2 / (每权重字节数)，对 4bit 权重约 4，量级仍是「个位数」，远低于拐点。
2. **选项分析**：B、C 描述的是大 batch 情形（权重被复用 N 次）；D 忽略了每权重的两次运算。
3. **业务延伸**：这个估算解释了「为什么 decode 必然是访存受限、为什么量化能直接提速」。也让工程师能快速估出「某卡上该模型 decode 理论极限 token/s ≈ 带宽 / 权重字节数」，作为优化目标参照。

### 第 49 题
【题型：单选题】【难度：进阶】
【题干】关于 decode 与 prefill 的算术强度，下列哪项描述正确？
【选项】
A. 两者算术强度相同，因为用的是同一批权重
B. decode 算术强度低（≈个位数）、访存受限；prefill 算术强度高（∝prompt 长度）、算力受限
C. prefill 算术强度低、访存受限
D. 两者都算力受限
【正确答案】B
【详细解析】
1. **核心原理**：算术强度取决于「权重被复用多少次」。decode 每步权重只服务极少量 token，复用次数低；prefill 权重被整个 prompt 的 token 复用，复用次数∝prompt 长度，算术强度随之上升。
2. **选项分析**：A 忽视了两阶段 batch 形态的本质差异；C 说反；D 忽略了 decode 的访存本质。
3. **业务延伸**：同一模型、同一权重，两阶段瓶颈截然不同，这是「分段优化」的根本依据。也解释了为什么长 prompt 的 prefill 反而「喂得饱 GPU」，而短 prompt 的 decode 常年「喂不饱」。

### 第 50 题
【题型：多选题】【难度：进阶】
【题干】用 profiler 判断「当前热点算子是访存受限」的依据包括？（多选）
【选项】
A. 该 kernel 的显存吞吐接近硬件峰值，而计算单元吞吐远低于峰值
B. 增大 batch 后该 kernel 的耗时占比下降
C. 该 kernel 的算术强度估算值远低于 roofline 拐点
D. 该 kernel 的线程数很少
【正确答案】ABC
【详细解析】
1. **核心原理**：profiler 能给出「计算吞吐 / 访存吞吐」相对峰值的百分比，据此直接判断受限类型；batch 敏感度与算术强度估算则是旁证。
2. **选项分析**：D 线程数少可能是「并行度不足」而非「访存受限」，是另一类问题，不能作为访存受限的证据。
3. **业务延伸**：区分「访存受限」与「并行度不足」很重要：前者要减数据量/增复用，后者要增大 grid/block、消除串行。把两者混淆会导致优化方向错误（例如给并行度不足的 kernel 做量化，毫无意义）。

### 第 51 题
【题型：单选题】【难度：进阶】
【题干】某模型 32 层、hidden 4096、FP16 的 KV。上下文 4096、并发 8 时，KV cache 大约占多少显存（按 KV 存储估算）？

A. 约 0.5 GB
B. 约 1.7 GB
C. 约 17 GB
D. 约 170 GB
【正确答案】C
【详细解析】
1. **核心原理**：KV 大小 ≈ 2（K+V）× 层数 × hidden × 长度 × batch × 字节数。代入：2×32×4096×4096×8×2 = 2×32=64；64×4096=262144；×4096≈1.07e9；×8≈8.6e9；×2 字节≈1.7e10 B ≈ 17 GB。
2. **选项分析**：A、B 少算了一到两个数量级（常见错误是漏乘 K/V 两份或漏乘 batch）；D 多了一个数量级。核心是「会算数量级」，而非背具体数字。
3. **业务延伸**：容量规划必须现算：2×层×hidden×长度×batch×字节。它能立刻回答「要支持 32K×8 并发需要多少显存」。注意此例中 KV（17 GB）往往比权重还大——这正是长上下文/高并发 OOM 的首要嫌疑，也是为什么需要 KV 量化/分页/分片。

【题型：多选题】【难度：进阶】

【正确答案】A

1. **核心原理**：量化数据在计算前可能需要还原（或使用专门的整数点积 kernel 免还原）。若实现走了「先反量化再算」的路径，反量化就进入热路径，成为额外开销。
2. **选项分析**：B、C 不是主要场景；D 否认了开销存在。
3. **业务延伸**：这解释了「为什么同样量化，不同实现速度差异大」——高效实现用整数点积直接算，避免完整反量化。选型/优化时要关注是否走了「免反量化」的高效路径。

【详细解析】

## 第三部分 · 高阶题（第 121–150 题）

### 第 121 题
【题型：多选题】【难度：高阶】
【题干】要设计一组能可靠回答「某优化到底有没有用」的端到端性能实验，必须满足？（多选）
【选项】
A. 有可复现的基线：固定模型、数据、序列长度、并发、编译配置与环境
B. 单变量改动，其余保持不变
C. 多次重复取稳态统计量（均值+方差），并观察分位延迟
D. 只跑一次、只看平均吞吐即可
【正确答案】ABC
【详细解析】
1. **核心原理**：可靠的性能结论依赖「可复现 + 可归因 + 抗噪」。固定环境保证可复现，单变量保证可归因，多次统计与分位保证抗噪。
2. **选项分析**：D 三个要素全违反——一次测量受噪声支配，只看平均会漏掉长尾与波动。
3. **业务延伸**：把实验设计固化成模板（基线脚本 + 指标面板 + 阈值），每次优化都按模板跑。这比任何单点技巧更能持续产生可信的性能改进，也便于团队协作与回溯。

### 第 122 题
【题型：单选题】【难度：高阶】
【题干】你算出某热点算子算术强度为 8 FLOP/Byte，而该卡拐点为 60 FLOP/Byte；同时 profiler 显示计算吞吐仅 15%、访存吞吐 85%。下一步最合理的动作是？
【选项】
A. 判定访存受限，优先减少访存量/提高复用（量化、融合、增大 batch）
B. 判定算力受限，优先优化计算指令

D. 直接换更高算力的卡
【正确答案】A
【详细解析】
1. **核心原理**：两条证据一致指向访存受限：算术强度（8）远低于拐点（60），且访存吞吐高、计算吞吐低。此时瓶颈是数据搬运。
2. **选项分析**：B 与两条证据矛盾；C 混淆了「并行度不足」与「访存受限」；D 换更高算力但不换带宽对访存受限几乎无效。
3. **业务延伸**：高阶调优的核心能力是「用多个独立证据交叉验证瓶颈类型」，避免单指标误判。判定后要选「针对瓶颈」的手段，并在改动后重新测量，确认瓶颈是否迁移（见第 133 题）。

### 第 123 题
【题型：多选题】【难度：高阶】
【题干】同一次请求同时包含长 prompt 的 prefill 与后续 decode，两阶段瓶颈不同。合理的整体调优思路有？（多选）
【选项】
