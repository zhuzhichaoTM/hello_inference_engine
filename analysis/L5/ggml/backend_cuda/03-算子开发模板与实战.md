## 3.1 GGML CUDA 算子标准开发模板（三段式）★ 背下来

所有 `ggml-cuda` 算子都遵循同一套结构。**记住这三段，你就能读任何一个算子。**

```
┌─ ① 设备端 functor（算什么）────────────────────────────────────  ┐
│  static __device__ __forceinline__ float op_xxx(float x) {     │
│      return <纯标量数学>;                                        │
│  }                                                              │
│  —— 无内存访问、无线程概念、可被 CPU 端复用为参考实现                  │
└────────────────────────────────────────────────────────────────┘
┌─ ② 启动器模板（怎么并行）──────────────────────────────────────┐
│  template <...> static __global__ void xxx_kernel(args...) {   │
│      <index 计算 → 边界检查 → 调 functor → 写回>                 │
│  }                                                             │
│  template <...> static void xxx_cuda(args..., cudaStream_t s) {│
│      <算 grid/block → ggml_cuda_kernel_launch(...)>             │
│  }                                                             │
└────────────────────────────────────────────────────────────────┘
┌─ ③ 主机端入口（取指针、算规模、选流）★ 签名固定 ────────────────┐
│  void ggml_cuda_op_xxx(ggml_backend_cuda_context & ctx,        │
│                        ggml_tensor * dst) {                    │
│      <取 src/dst 指针 → ASSERT 类型与布局 → 算元素数 → 调 ②>      │
│  }                                                             │
└────────────────────────────────────────────────────────────────┘
```

**③ 的签名是铁律**：`void ggml_cuda_op_xxx(ggml_backend_cuda_context & ctx, ggml_tensor * dst)`。
所有输入从 `dst->src[i]` 取，**没有任何额外参数**——这就是为什么 `.cuh` 里能统一声明它们。

### 入口函数的标准动作清单（每个算子都做这些）

```cpp
void ggml_cuda_op_xxx(ggml_backend_cuda_context & ctx, ggml_tensor * dst) {
    // 1. 取张量与指针
    const ggml_tensor * src0 = dst->src[0];
    const void * src0_d = src0->data;
    void * dst_d = dst->data;

    // 2. 取流 ★ 永远是 ctx.stream()
    cudaStream_t stream = ctx.stream();

    // 3. 布局/类型断言（防错，Debug 版生效）
    GGML_ASSERT(ggml_is_contiguous(src0));
    GGML_ASSERT(src0->type == dst->type);

    // 4. 算规模
    const int k = ggml_nelements(src0);

    // 5. 按类型分派到 ②（模板必须显式实例化，不能运行时决定）
    if (src0->type == GGML_TYPE_F16) {
        xxx_cuda<op>((const half *)src0_d, (half *)dst_d, k, stream);
    } else {
        xxx_cuda<op>((const float *)src0_d, (float *)dst_d, k, stream);
    }
}
```

### 标准启动器模板（可直接抄）

```cpp
template <float (*op)(float), typename T>
static __global__ void xxx_kernel(const T * x, T * dst, const int k) {
    const int i = blockDim.x*blockIdx.x + threadIdx.x;   // 1D 展平索引
    if (i >= k) return;                                  // ★ 边界检查必须有
    dst[i] = (T)op((float)x[i]);
}

template <float (*op)(float), typename T>
static void xxx_cuda(const T * x, T * dst, const int k, cudaStream_t stream) {
    const int num_blocks = (k + CUDA_XXX_BLOCK_SIZE - 1) / CUDA_XXX_BLOCK_SIZE;  // 向上取整
    const ggml_cuda_kernel_launch_params lp =
        ggml_cuda_kernel_launch_params((dim3)num_blocks, CUDA_XXX_BLOCK_SIZE, 0, stream);
    ggml_cuda_kernel_launch(xxx_kernel<op, T>, lp, x, dst, k);   // ★ 不要直接 <<<>>>
}
```

**两个关键约定**：
1. **`ggml_cuda_kernel_launch`（`common.cuh:1699`）而不是 `<<<>>>`**：它内部处理 PDL（Hopper+ 的 kernel 重叠启动）。直接写 `<<<>>>` 会失去这个优化；
2. **`blockDim.x` 用宏**（如 `CUDA_SILU_BLOCK_SIZE`）：统一在 `.cuh` 里定义，便于调优。

## 3.2 精读一：`unary.cu` —— 最小完整算子（721 行）

### ① 设备端 functor（`unary.cu:5-137`）

```cpp
static __device__ __forceinline__ float op_silu(float x) {
    return ggml_cuda_op_silu_single(x);          // unary.cu:40
}
// unary.cuh 里定义（可被 CPU 复用为参考）：
__device__ __forceinline__ float ggml_cuda_op_silu_single(float x) {
    return x / (1.0f + expf(-x));                 // unary.cuh:110
}
```

**设计要点**：
- 每个 functor 是**纯标量函数**，`__forceinline__` 强制内联（否则函数指针模板无法优化）；
- 复杂的（如 GELU）抽到 `unary.cuh`，因为**别处也要用**（GLU 的 gate 计算复用同一公式）；
- `op_step` 返回 `x > 0.0f`（bool→float 隐式转换），这是 ggml 的写法风格。

### ② 启动器模板（`unary.cu:117-135`）

```cpp
template <float (*op)(float), typename T>
static __global__ void unary_op_kernel(const T * x, T * dst, const int k) {
    ggml_cuda_pdl_lc();                                  // :118  PDL: 提前取 launch 控制
    const int i = blockDim.x*blockIdx.x + threadIdx.x;
    if (i >= k) return;
    ggml_cuda_pdl_sync();                                // :125  PDL: 等前序 kernel 的数据就绪
    dst[i] = (T)op((float)x[i]);
}

template <float (*op)(float), typename T>
static void unary_cuda(const T * x, T * dst, const int k, cudaStream_t stream) {
    const int num_blocks = (k + CUDA_NEG_BLOCK_SIZE - 1) / CUDA_NEG_BLOCK_SIZE;  // :129
    const ggml_cuda_kernel_launch_params launch_params =
        ggml_cuda_kernel_launch_params((dim3)num_blocks, CUDA_NEG_BLOCK_SIZE, 0, stream);  // :130
    ggml_cuda_kernel_launch(unary_op_kernel<op, T>, launch_params, x, dst, k);   // :131
}
```

**PDL 三件套**（Hopper+ 才生效，`common.cuh:133/139`）：
```cpp
ggml_cuda_pdl_lc()    // launch control：读取 launch 依赖，让 kernel 提前开始
ggml_cuda_pdl_sync()  // 在真正读输入数据前等前序 kernel 写完
```
**含义**：kernel 的"启动"和"读数据"解耦，连续 kernel 可重叠启动。`pdl_sync()` 必须放在**第一次读全局内存之前**——这是写 PDL kernel 的唯一纪律。

**注意**：`float (*op)(float)` 作为**模板参数**（不是函数参数）。这样每个 op 生成独立 kernel 实例，编译器能完全内联 op。如果写成运行时函数指针参数，会有间接调用开销。

### ③ 主机端入口（`unary.cu:137-155`）

```cpp
template <float (*op)(float)>
void ggml_cuda_op_unary(ggml_backend_cuda_context & ctx, ggml_tensor * dst) {
    const ggml_tensor * src0 = dst->src[0];
    const void * src0_d = src0->data;
    void * dst_d = dst->data;
    cudaStream_t stream = ctx.stream();                    // :141  ★ 标准取流

    GGML_ASSERT(ggml_is_contiguous(src0));                 // :143  布局约束
    GGML_ASSERT(src0->type == GGML_TYPE_F32 || src0->type == GGML_TYPE_F16);
    GGML_ASSERT( dst->type == GGML_TYPE_F32 ||  dst->type == GGML_TYPE_F16);
    GGML_ASSERT(src0->type == dst->type);                  // :146  类型必须一致

    if (src0->type == GGML_TYPE_F16) {
        unary_cuda<op>((const half *)src0_d, (half *)dst_d, ggml_nelements(src0), stream);
    } else {
        unary_cuda<op>((const float *)src0_d, (float *)dst_d, ggml_nelements(src0), stream);
    }
}

// 每个具体 op 只是一个薄封装（:157 起，30 个几乎一样的函数）
void ggml_cuda_op_silu(ggml_backend_cuda_context & ctx, ggml_tensor * dst) {
    ggml_cuda_op_unary<op_silu>(ctx, dst);
}
```

**为什么 30 个函数几乎一样？** 因为 op 是**模板参数**，`ggml_cuda_op_silu` 和 `ggml_cuda_op_gelu` 编译出的是**两个不同的 kernel**。这些薄封装存在的唯一理由是给 `ggml-cuda.cu` 的 switch 提供统一签名的函数指针。

### GLU 变体：带 gate 的算子（`unary.cu:283-330`）

```cpp
template <float (*op)(float), typename T>
static __global__ void unary_gated_op_kernel(const T * x, const T * g, T * dst,
        const int64_t k, const int64_t n, const int64_t o0, const int64_t o1) {
    ggml_cuda_pdl_lc();
    const int64_t i = int64_t(blockDim.x)*blockIdx.x + threadIdx.x;
    if (i >= k) return;

    // ★ 核心：从展平索引反算 2D 偏移，支持 x 和 g 在不同张量/不同行跨距
    const int64_t j0 = (i / n) * o0 + (i % n);
    const int64_t j1 = o0 == o1 ? j0 : (i / n) * o1 + (i % n);

    ggml_cuda_pdl_sync();
    dst[i] = (T)(op((float)x[j0]) * (float)g[j1]);
}
```
**`j0/j1` 的 `o0 == o1` 优化**：SwiGLU 常见形态是 `x` 和 `g` 在**同一个张量**里（前半是 gate，后半是 up），此时跨距相同，省一次除法。这是**访存密集算子的典型微优化**。

### 精读结论表

| 观察 | 位置 | 工程含义 |
|---|---|---|
| functor 作模板参数 | `unary.cu:117` | 完全内联，无间接调用 |
| PDL lc/sync 夹住读内存 | `:118` / `:125` | Hopper 上 kernel 重叠启动 |
| `ggml_cuda_kernel_launch` 而非 `<<<>>>` | `:131` | 自动走 PDL 路径 |
| 类型分派在主机端 | `:148` | 模板实例必须编译期确定 |
| 30 个薄封装 | `:157+` | 为 switch 提供统一签名 |

## 3.3 精读二：`softmax.cu` —— 归约类算子（480 行）

比 unary 复杂一个档次：**需要块内归约（max/sum）**，且用**模板特化消除循环边界**。

### 核心 kernel（`softmax.cu:61`）

```cpp
template <bool use_shared, int ncols_template, int block_size_template, typename T>
static __global__ void soft_max_f32(
        const float * x, const T * mask, const float * sinks, float * dst, const soft_max_params p) {
    const int ncols = ncols_template == 0 ? p.ncols : ncols_template;   // ★ 编译期或运行期

    const int tid = threadIdx.x;
    const int64_t i03 = blockIdx.z, i02 = blockIdx.y, i01 = blockIdx.x;
    const int rowx = blockIdx.x + blockIdx.y*gridDim.x + blockIdx.z*gridDim.x*gridDim.y;  // 展平行号

    x    += int64_t(rowx)*ncols;
    mask += (i11*p.nb11 + i12*p.nb12 + i13*p.nb13)/sizeof(T) * (mask != nullptr);  // ★ mask 可选
    dst  += int64_t(rowx)*ncols;

    const float slope = get_alibi_slope(p.max_bias, i02, p.n_head_log2, p.m0, p.m1);  // ALiBi

    extern __shared__ float data_soft_max_f32[];
    float * buf_iw = data_soft_max_f32;                    // warp 间通信缓冲
    float * vals = use_shared ? buf_iw + WARP_SIZE : dst;  // ★ 中间值缓存位置

    float max_val = sinks ? sinks[i02] : -INFINITY;        // ★ attention sink

    // ── Pass 1：找 max（online 式，边读边更新）──
    #pragma unroll
    for (int col0 = 0; col0 < ncols; col0 += block_size) {
        const int col = col0 + tid;
        if (ncols_template == 0 && col >= ncols) break;
        const float val = x[col]*p.scale + (mask ? slope*t2f32(mask[col]) : 0.0f);
        vals[col] = val;                                   // 缓存，避免二次读全局内存
        max_val = max(max_val, val);
    }
    max_val = block_reduce<block_reduce_method::MAX, block_size_template>(max_val, buf_iw);

    // ── Pass 2：算 exp 和 sum ──
    float tmp = 0.0f;
    #pragma unroll
    for (int col0 = 0; col0 < ncols; col0 += block_size) {
        const int col = col0 + tid;
        if (ncols_template == 0 && col >= ncols) break;
        const float val = expf(vals[col] - max_val);
        tmp += val;
        vals[col] = val;                                   // 覆盖缓存
    }
    if (block_size > WARP_SIZE) __syncthreads();           // ★ 复用 buf_iw 前必须同步
    tmp = block_reduce<block_reduce_method::SUM, block_size_template>(tmp, buf_iw);
    if (sinks) tmp += expf(sinks[i02] - max_val);

    const float inv_sum = 1.0f / tmp;                      // ★ 一次除法代替 N 次

    // ── Pass 3：写回 ──
    #pragma unroll
    for (int col0 = 0; col0 < ncols; col0 += block_size) {
        const int col = col0 + tid;
        if (ncols_template == 0 && col >= ncols) return;
        dst[col] = vals[col] * inv_sum;
    }
}
```

**必须理解的 5 个设计**：

| # | 设计 | 原因 |
|---|---|---|
| 1 | **三次 pass（max→sum→写回）** | 数值稳定（减 max 防溢出）；`vals` 缓存避免重复读全局内存 |
| 2 | **`ncols_template` 模板参数** | 编译期已知 ncols 时循环可完全展开、边界检查消除。`0` = 运行期未知（fallback） |
| 3 | **`vals` 放 shared 还是 dst** | `use_shared` 控制。放 dst 省 shared mem；shared 版需要 `__syncthreads()` 保护 `buf_iw` 复用 |
| 4 | **`inv_sum = 1.0f/tmp`** | 把 N 次除法变成 1 次除法 + N 次乘法 |
| 5 | **`block_reduce<METHOD, BLOCK_SIZE>`** | 模板化归约，`BLOCK_SIZE` 已知时可展开成 shuffle 树 |

### 分发层：模板列表 + 折叠表达式（`softmax.cu:335`）

```cpp
template<int... Ns, typename T>
static void launch_soft_max_kernels(const float * x, const T * mask, const float * sinks, float * dst,
                             const soft_max_params & p, cudaStream_t stream, dim3 block_dims, dim3 block_nums, size_t nbytes_shared) {
    auto launch_kernel = [=](auto I) -> bool {
        constexpr int ncols = decltype(I)::value;
        constexpr int block = (ncols > 1024 ? 1024 : ncols);
        if (p.ncols == ncols) {
            CUDA_SET_SHARED_MEMORY_LIMIT((soft_max_f32<true, ncols, block, T>), smpbo);
            soft_max_f32<true, ncols, block><<<block_nums, block_dims, nbytes_shared, stream>>>(x, mask, sinks, dst, p);
            return true;
        }
        return false;
    };

    // ★ C++17 折叠表达式：依次尝试每个 ncols 特化，命中即返回
    if ((launch_kernel(std::integral_constant<int, Ns>{}) || ...)) return;

    // 未命中 → 通用版（ncols_template=0）
    CUDA_SET_SHARED_MEMORY_LIMIT((soft_max_f32<true, 0, 0, T>), smpbo);
    soft_max_f32<true, 0, 0><<<block_nums, block_dims, nbytes_shared, stream>>>(x, mask, sinks, dst, p);
}

// 调用点（softmax.cu:411）：枚举常见 ncols
launch_soft_max_kernels<32, 64, 128, 256, 512, 1024, 2048, 4096>(...);
```

**这是 ggml-cuda 处理"编译期常量优化"的标准套路**：
- 预先实例化常见规模（32/64/.../4096）；
- 运行时用折叠表达式匹配，命中则用特化 kernel（快），未命中回退通用版（慢但正确）；
- **代价**：二进制变大（8 个实例 × 2 类型）。这就是 `template-instances/` 目录存在的根源。

### 共享内存需求与两条路径（`softmax.cu:396`）

```cpp
int nth = WARP_SIZE;
while (nth < ncols_x && nth < CUDA_SOFT_MAX_BLOCK_SIZE) nth *= 2;   // :398  块大小翻倍到够用
const dim3 block_dims(nth, 1, 1);
const dim3 block_nums(params.ne01, params.ne02, params.ne03);
const size_t nbytes_shared = (GGML_PAD(ncols_x, WARP_SIZE) + WARP_SIZE)*sizeof(float);  // :401

if (nbytes_shared <= smpbo) {
    // ★ 路径 A：ncols 能塞进 shared → 常规 kernel（模板列表匹配）
    launch_soft_max_kernels<32, 64, ..., 4096>(...);
} else {
    // ★ 路径 B：ncols 太大（如长上下文 attention）→ 跨 SM 并行
    if (supports_cooperative_launch && ncols_x/nrows > 8192 && mask==nullptr && sinks==nullptr
        && scale==1.0f && max_bias==0.0f) {
        // 协作组：整个 grid 同步，一个 row 摊到所有 SM
        ggml_cuda_pool_alloc<float> tmp_maxs_alloc(ctx.pool(), nsm*sizeof(float));
        ggml_cuda_pool_alloc<float> tmp_sums_alloc(ctx.pool(), nsm*sizeof(float));
        cudaLaunchCooperativeKernel(soft_max_f32_parallelize_cols, dim3(nsm,1,1), dim3(WARP_SIZE*8,1,1), ...);
    } else {
        // 兜底：use_shared=false，vals 直接用 dst，少用 shared mem
        soft_max_f32<false, 0, 0><<<block_nums, block_dims, WARP_SIZE*sizeof(float), stream>>>(...);
    }
}
```

**三条路径的取舍**：
| 路径 | 条件 | 策略 |
|---|---|---|
| A 常规 | `nbytes_shared <= smpbo` | 一个 row 一个 block，shared 缓存中间值 |
| B1 协作组 | ncols 极大 + 无 mask/sink/scale | 一个 row 摊到全 grid，用 `cudaLaunchCooperativeKernel` |
| B2 兜底 | 其他 | `use_shared=false`，中间值直接写 dst（省 shared，但多读一次全局） |

> **`ctx.pool()` 在这里被用到**——这是模块一讲的 `ggml_cuda_pool_alloc` 的真实用例。
> ⚠️ **注意一个易误读点**：`ggml_cuda_pool_alloc<float>(pool, size)` 的 `size` 是**元素个数**（内部 ×sizeof(T)），但这里传的是 `nsm*sizeof(float)`，等于分配了 `nsm*4` 个 float（**超额 4 倍**）。安全（多分配无害）但不精确——**读 ggml 代码时永远先确认 alloc 的参数单位**。

### 参数结构体 `soft_max_params`（`softmax.cu:27`）

```cpp
struct soft_max_params {
    int64_t nheads; uint32_t n_head_log2;
    int64_t ncols, nrows_x, nrows_y;
    int64_t ne00, ne01, ne02, ne03;
    int64_t nb11, nb12, nb13;      // mask 的 stride
    int64_t ne12, ne13;
    float scale, max_bias, m0, m1;  // ALiBi 的 m0/m1
};
```
**为什么用结构体而不是一堆参数？** CUDA kernel 参数区有大小限制（4KB，较新架构 32KB）。**一个大 struct 只占一个参数槽**，比 17 个独立参数更省且更易扩展。**自定义算子参数多时应照此办理。**

**CUDA 侧代码（照抄模板）：**

```cpp
// ── unary.cu：① functor ──
static __device__ __forceinline__ float op_softsign(float x) {
    return x / (1.0f + fabsf(x));
}

// ── unary.cu：③ 入口（② 的 unary_cuda 完全复用，零改动！）──
void ggml_cuda_op_softsign(ggml_backend_cuda_context & ctx, ggml_tensor * dst) {
    ggml_cuda_op_unary<op_softsign>(ctx, dst);
}

// ── unary.cuh：声明 ──
```

### 路线 B：新增一个独立算子（2 小时）

以"元素级 `y = a*x + b`（仿射变换）"为例，因为它需要读 `op_params`，覆盖更多知识点。

**步骤 1：定义 op（`include/ggml.h`）**
```cpp
enum ggml_op {
    ...
    GGML_OP_AFFINE,      // 加在 GGML_OP_COUNT 之前
    GGML_OP_COUNT,
};
```

**步骤 2：图构建 API（`include/ggml.h` 声明 + `src/ggml.c` 实现）**
```c
struct ggml_tensor * ggml_affine(struct ggml_context * ctx, struct ggml_tensor * a, float scale, float bias) {
    struct ggml_tensor * result = ggml_dup_tensor(ctx, a);
    ggml_set_op_params(result, &scale, sizeof(float));                    // op_params[0]
    ggml_set_op_params(result, &bias,  sizeof(float));                    // op_params[1]
    result->op     = GGML_OP_AFFINE;
    result->src[0] = a;
    return result;
}
```
> **`op_params` 是算子传参的标准机制**：一个 `char op_params[GGML_MAX_OP_PARAMS]` 字节数组，用 `ggml_set_op_params`/`memcpy` 读写。**结构体参数也走这里**（见 `soft_max_params` 的 scale/max_bias 从 `dst->op_params` 读出，`softmax.cu:472`）。

**步骤 3：CUDA 实现（新建 `affine.cu` + `affine.cuh`）**
```cpp
// affine.cuh
#pragma once
#include "common.cuh"
#define CUDA_AFFINE_BLOCK_SIZE 256
void ggml_cuda_op_affine(ggml_backend_cuda_context & ctx, ggml_tensor * dst);

// affine.cu
#include "affine.cuh"
template <typename T>
static __global__ void affine_kernel(const T * x, T * dst, const int k, const float scale, const float bias) {
    const int i = blockDim.x*blockIdx.x + threadIdx.x;
    if (i >= k) return;
    dst[i] = (T)((float)x[i] * scale + bias);
}
template <typename T>
static void affine_cuda(const T * x, T * dst, const int k, float scale, float bias, cudaStream_t stream) {
    const int nb = (k + CUDA_AFFINE_BLOCK_SIZE - 1) / CUDA_AFFINE_BLOCK_SIZE;
    const ggml_cuda_kernel_launch_params lp =
        ggml_cuda_kernel_launch_params((dim3)nb, CUDA_AFFINE_BLOCK_SIZE, 0, stream);
    ggml_cuda_kernel_launch(affine_kernel<T>, lp, x, dst, k, scale, bias);
}
void ggml_cuda_op_affine(ggml_backend_cuda_context & ctx, ggml_tensor * dst) {
    const ggml_tensor * src0 = dst->src[0];
    float scale, bias;
    memcpy(&scale, (const float *) dst->op_params + 0, sizeof(float));   // ★ 读 op_params
    memcpy(&bias,  (const float *) dst->op_params + 1, sizeof(float));
    cudaStream_t stream = ctx.stream();
    GGML_ASSERT(ggml_is_contiguous(src0));
    GGML_ASSERT(src0->type == dst->type);
    const int k = ggml_nelements(src0);
    if (src0->type == GGML_TYPE_F16) {
        affine_cuda((const half *)src0->data, (half *)dst->data, k, scale, bias, stream);
    } else {
        affine_cuda((const float *)src0->data, (float *)dst->data, k, scale, bias, stream);
    }
}
```

**步骤 4：注册（`ggml-cuda.cu` 两处）**
```cpp
// compute_forward（:2068 的 switch 内）
case GGML_OP_AFFINE:
    ggml_cuda_op_affine(ctx, dst);
    break;

// supports_op（:5136 的 switch 内）
case GGML_OP_AFFINE:
    return ggml_is_contiguous(op->src[0]);
```

**步骤 5：CMake 注册** —— `src/ggml-cuda/CMakeLists.txt:105` 用的是 `file(GLOB GGML_SOURCES_CUDA "*.cu")`，**新 `.cu` 会自动被包含**，只需重跑一次 cmake 让它重新 glob（`cmake -S . -B build`）。新 `.cuh` 同理（`:102` glob `*.cuh`）。

**步骤 6：CPU 参考实现**（`src/ggml-cpu/ops.cpp`）
```cpp
static void ggml_compute_forward_affine(const struct ggml_compute_params * params, struct ggml_tensor * dst) {
    const struct ggml_tensor * src0 = dst->src[0];
    float scale, bias;
    memcpy(&scale, (const float *) dst->op_params + 0, sizeof(float));
    memcpy(&bias,  (const float *) dst->op_params + 1, sizeof(float));
    const int ith = params->ith, nth = params->nth;
    const int64_t k = ggml_nelements(src0);
    const int64_t per = (k + nth - 1) / nth;
    for (int64_t i = ith*per; i < MIN((ith+1)*per, k); i++) {
        ((float *)dst->data)[i] = ((const float *)src0->data)[i] * scale + bias;
    }
}
// 并在 ggml_compute_forward switch 里加 case
```

> **CPU 实现是必须的**：`ggml_backend_sched` 在 CUDA 不支持某 op 时会回退 CPU；测试框架也用 CPU 结果做 golden reference。

## 3.5 算子优化方法论

### 优化决策树（先判断算子类型）

```
这个算子是？
├─ 访存密集（unary / cpy / binbcast / norm）
│   → 优化方向：减少访存次数、向量化加载、融合相邻算子
│   · float4 向量化：一次读 16 字节而不是 4 字节
│   · 算子融合：Silu + Mul → unary_gated_op（一次读、一次写）
│   · 避免中间落盘：vals 缓存到 shared/寄存器
│
├─ 计算密集（mul_mat / mmq / conv）
│   → 优化方向：tensor core、tile 复用、指令级并行
│   · mma.cuh 的 PTX 指令（f16/bf16/tf32/int8）
│   · shared memory tile 复用（mmq-load-tiles.cuh）
│   · cp.async 流水线（cp-async.cuh）
│
└─ 归约类（softmax / norm / sum_rows）
    → 优化方向：warp shuffle 归约、避免 __syncthreads__
    · block_reduce<METHOD> 模板
    · 一次除法代替 N 次（inv_sum）
    · 多 pass 时缓存中间值
```

### 六条具体优化手段（附源码对标）

| # | 手段 | 源码对标 | 收益 |
|---|---|---|---|
| 1 | **向量化访存** | `cpy.cu` 的 `float4` 路径 | 带宽利用率 ×2~4 |
| 2 | **算子融合** | `unary.cu:283` unary_gated；`ggml-cuda.cu:4509` graph_optimize 的 MUL_MAT+bias+GLU | 省一次全局内存往返 |
| 3 | **模板特化消循环** | `softmax.cu:335` ncols 特化列表 | 边界检查+循环展开 |
| 4 | **shared memory tile** | `mmq-load-tiles.cuh` | 复用提升算术强度 |
| 5 | **warp shuffle 归约** | `reduce_rows.cuh` / `block_reduce` | 免 `__syncthreads` |
| 6 | **PDL 重叠启动** | `common.cuh:1699` + `pdl_lc/sync` | Hopper 上省 kernel 间隔 |

### 线程块/网格调优方法

```cpp
// 1D 元素级：block 固定，grid 覆盖
const int num_blocks = (k + BLOCK - 1) / BLOCK;      // 向上取整，多算的线程靠边界检查退出
// 2D/3D：把 row 维度映射到 blockIdx
dim3 block_nums(params.ne01, params.ne02, params.ne03);
// 每 block 线程数：warp 倍数，通常 128/256；归约类用 2 的幂便于 shuffle
int nth = WARP_SIZE;  while (nth < ncols && nth < 1024) nth *= 2;
```
**调优经验**：
- 元素级算子：**block=256，grid 尽量大**（SM 数量 × 数倍）以掩盖延迟；
- 归约算子：**block 覆盖一行**，避免跨 block 归约（需协作组，代价高）；
- **shared mem 用量决定 occupancy**：`nbytes_shared` 越大，同时驻留的 block 越少。softmax 的路径 B2（`use_shared=false`）就是为省 shared 而设。

### 量化精度与性能平衡

```
精度 ←→ 性能 的旋钮：
├─ 量化格式：Q4_0(快/低精) → Q5_K → Q6_K → Q8_0 → F16 → F32(慢/高精)
├─ 计算精度：dst->type = F32（默认）vs 用 GGML_PREC_F32 保精度
├─ 是否用 tensor core：mma 路径（快）vs 标量路径（准，如 MMQ_FORCE 的 dp4a）
└─ 反量化时机：MMVQ 直接点积（快）vs 显式 dequantize（准）
```

## 3.6 常见问题排错（源码级）

| 症状 | 根因 | 排查步骤 |
|---|---|---|
| **算子从不被调度**（走 CPU 或报错） | 忘了改 `supports_op` | `grep -n "GGML_OP_XXX" ggml-cuda.cu` 确认两处都有；加 `GGML_LOG_DEBUG` 打印 |
| **编译报错 "undefined reference"** | 忘了在 CMakeLists 加 `.cu`，或忘了模板实例化 | 检查 `src/ggml-cuda/CMakeLists.txt`；模板需显式实例化（见 `template-instances/`） |
| **显存泄漏 / OOM 逐渐增长** | `cudaMalloc` 未配对 `cudaFree`；或 `pool_alloc` 生命周期错 | 用 `ggml_cuda_pool_alloc<T>`（RAII）；`compute-sanitizer --tool memcheck` |
| **设备同步报错 (illegal memory access)** | 越界/未初始化指针；`cudaGetLastError` 查不到（异步） | `compute-sanitizer ./binary`；检查边界 `if (i >= k) return;` |
| **结果错乱但无报错** | `actual_size != size` 导致 stride 错；或漏 `ggml_cuda_set_device` | 打印 `actual_size`；确认多卡下 set_device |
| **推理卡顿（首次慢，之后快）** | CUDA Graph 热身（需 2 次）；或首次 kernel 加载 | 属正常；持续慢则查 occupancy（shared mem 过大） |
| **精度异常（量化后）** | MMQ/MMVQ 路径的 scale 处理；或 `GGML_CUDA_FORCE_MMQ` | 与 CPU 结果逐元素对比；试 `-ngl 0` 走 CPU 对照 |
| **多卡下结果错** | 虚拟/物理设备混淆；缺 `ggml_cuda_get_physical_device` | 检查 `physical_device` 映射 |

### 调试手段速查


## 3.8 模块三学习重点提炼

### 必背 5 条

| # | 结论 |
|---|---|
| 1 | 算子 = **functor（算什么）+ kernel/launcher（怎么并行）+ op 入口（取指针）** 三段式 |
| 2 | op 入口签名**铁律**：`void ggml_cuda_op_xxx(ggml_backend_cuda_context & ctx, ggml_tensor * dst)` |
| 3 | 新算子必须改 **compute_forward + supports_op 两处**（漏一处就静默失效） |
| 4 | 用 `ggml_cuda_kernel_launch`（非 `<<<>>>`）+ `ctx.stream()`（非自建流） |
| 5 | 临时显存用 `ggml_cuda_pool_alloc<T>`；**注意 alloc 参数是元素个数** |

### 易错点

| 易错 | 后果 | 正解 |
|---|---|---|
| 只在 compute_forward 注册 | 永不调度 | supports_op 也注册 |
| kernel 无边界检查 | 越界崩溃 | `if (i >= k) return;` |
| 直接 `<<<>>>` 启动 | 丢 PDL 优化 | `ggml_cuda_kernel_launch` |
| `pool_alloc` 参数单位搞错 | 显存浪费/错位 | 参数是**元素数** |
| 忘写 CPU 参考实现 | 回退失败、无法测正确性 | 补 ggml-cpu/ops.cpp |
| 模板未显式实例化 | 链接错误 | 加 `template void ...<>();` |

### CMake 误区

`src/ggml-cuda/CMakeLists.txt:105` 的 `file(GLOB "*.cu")` 会收集普通 `.cu`，但量化/FlashAttention 的 `template-instances/` 是分别 glob 的；新增依赖架构/类型的模板时，不能只依赖普通 glob，要检查对应实例宏和 `GGML_CUDA_FA_QUANTS` 配置。

### “支持”不等于“执行”

`ggml_backend_cuda_device_supports_op`（`:5136`）还会检查：

```text
src buffer 是否属于当前 CUDA device
类型组合
nb[0] 是否连续
layout/stride
op_params 限制
```

因此测试自定义算子时，要分别验证：

```text
直接调用入口
通过 compute_forward 执行
通过 scheduler 的 supports_op 调度
CPU fallback
```
